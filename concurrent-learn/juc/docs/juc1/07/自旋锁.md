# 自旋锁

## 什么是自旋锁

自旋锁（Spin Lock）是一种**忙等待**的同步机制。当线程尝试获取锁失败时，不会进入阻塞状态，而是持续循环检查锁的状态直到成功获取。

## 为什么需要自旋锁

传统的阻塞锁存在以下问题：
- **上下文切换开销大**：线程阻塞和唤醒需要操作系统介入，消耗大量CPU周期
- **响应延迟不可预测**：从阻塞到唤醒的时间不确定
- **缓存失效**：线程切换可能导致CPU缓存失效

对于**临界区执行时间很短**的场景，自旋锁通过避免上下文切换可以获得更好的性能。

## `CAS` 操作的核心作用

### `CAS` 是什么
`CAS`（Compare-And-Swap）是实现自旋锁的关键原子操作。它包含三个操作数：
- **内存位置V**
- **预期值A**
- **新值B**

只有当 `V` 的值等于 `A` 时，才将 `V` 更新为 `B`，否则不更新。整个过程是原子性的。

### 为什么要用 `CAS` 实现自旋锁

相比传统锁机制，`CAS` 提供了：
- **无锁化编程**：不需要操作系统级别的锁支持
- **原子性保证**：硬件级别的原子操作确保线程安全
- **高性能**：避免了重量级的系统调用

## 自旋锁的实现细节

### 基础版本
```java
public class SimpleSpinLock {
    private AtomicReference<Thread> owner = new AtomicReference<>();
    
    public void lock() {
        Thread current = Thread.currentThread();
        // CAS操作尝试获取锁
        while (!owner.compareAndSet(null, current)) {
            // 获取失败则自旋等待
        }
    }
    
    public void unlock() {
        Thread current = Thread.currentThread();
        // CAS操作释放锁
        owner.compareAndSet(current, null);
    }
}
```

### 改进版本 - 支持可重入
```java
public class ReentrantSpinLock {
    private AtomicReference<Thread> owner = new AtomicReference<>();
    private int count = 0;
    
    public void lock() {
        Thread current = Thread.currentThread();
        // 如果当前线程已持有锁
        if (current == owner.get()) {
            count++;
            return;
        }
        
        // CAS操作尝试获取锁
        while (!owner.compareAndSet(null, current)) {
            // 自旋等待
        }
        count = 1;
    }
    
    public void unlock() {
        Thread current = Thread.currentThread();
        if (current == owner.get()) {
            if (count > 1) {
                count--;
            } else {
                // 最后一次释放锁
                owner.compareAndSet(current, null);
            }
        }
    }
}
```


## 自旋锁的性能考量

### 优势场景
- **临界区极短**：锁持有时间在纳秒到微秒级别
- **低竞争环境**：很少有多个线程同时争抢同一个锁
- **延迟敏感应用**：需要确定性的响应时间

### 劣势场景
- **高竞争环境**：多个线程频繁争抢锁资源
- **长临界区**：锁持有时间较长
- **CPU资源紧张**：系统负载已经很高

## JDK中的自旋锁应用

Java并发包中的许多组件都使用了自旋锁的思想：

### synchronized的优化
JDK 1.6之后，`synchronized`关键字进行了大量优化，其中包括：
- **偏向锁**：消除无竞争情况下的同步开销
- **轻量级锁**：使用CAS操作替代重量级互斥量
- **自适应自旋**：根据历史竞争情况调整自旋时间

### `AQS` 中的应用
`AbstractQueuedSynchronizer`在尝试获取锁时会先进行有限次数的自旋：

```java
// 简化的AQS获取逻辑
final boolean acquireQueued(final Node node, int arg) {
    boolean failed = true;
    try {
        boolean interrupted = false;
        for (;;) {
            final Node p = node.predecessor();
            // 如果前驱是头节点，尝试获取锁
            if (p == head && tryAcquire(arg)) {
                setHead(node);
                p.next = null; // help GC
                failed = false;
                return interrupted;
            }
            // 在某些情况下会自旋而不是直接阻塞
            if (shouldParkAfterFailedAcquire(p, node) &&
                parkAndCheckInterrupt())
                interrupted = true;
        }
    } finally {
        if (failed)
            cancelAcquire(node);
    }
}
```

## 自旋锁的高级变体

### Ticket Lock
```java
public class TicketLock {
    private AtomicInteger serviceNum = new AtomicInteger(); // 正在服务的号码
    private AtomicInteger ticketNum = new AtomicInteger();  // 下一个可发放的号码
    
    public void lock() {
        int myTicket = ticketNum.getAndIncrement();
        while (serviceNum.get() != myTicket) {
            // 等待叫号
        }
    }
    
    public void unlock() {
        serviceNum.incrementAndGet();
    }
}
```


### MCS Lock
```java
public class MCSLock {
    private AtomicReference<MCSNode> tail = new AtomicReference<>();
    
    static class MCSNode {
        volatile MCSNode next;
        volatile boolean blocked = true;
    }
    
    ThreadLocal<MCSNode> node = ThreadLocal.withInitial(MCSNode::new);
    
    public void lock() {
        MCSNode currentNode = node.get();
        MCSNode predecessor = tail.getAndSet(currentNode);
        if (predecessor != null) {
            predecessor.next = currentNode;
            while (currentNode.blocked) { } // 自旋等待
        }
    }
    
    public void unlock() {
        MCSNode currentNode = node.get();
        if (currentNode.next == null) {
            if (tail.compareAndSet(currentNode, null)) {
                return;
            }
            while (currentNode.next == null) { } // 等待next指针设置
        }
        currentNode.next.blocked = false;
        currentNode.next = null;
    }
}
```


## 最佳实践建议

### 选择合适的锁机制
1. **临界区很短且竞争不激烈** → 自旋锁
2. **临界区较长或高竞争** → 阻塞锁
3. **读多写少** → 读写锁
4. **无锁算法可行** → 原子类或无锁数据结构

### 性能调优参数
```bash
# JVM自旋相关参数
-XX:PreBlockSpin=10          # 默认自旋次数
-XX:+UseSpinning             # 启用自旋锁优化
-XX:UseBoundThreads=true     # 绑定线程到CPU核心
```
