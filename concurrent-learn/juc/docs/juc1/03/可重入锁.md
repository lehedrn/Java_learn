# 可重入锁 (Reentrant Lock)

## 定义

可重入锁，又名递归锁，是指**同一线程**可以多次获取**同一把锁**，而不会出现死锁的情况。当一个线程已经持有某个锁时，它可以再次获取该锁而不会被阻塞。

## 可重入锁原理
其核心原理是通过记录锁的持有者和持有次数来实现。
### 实现原理
1. 计数器机制
- 每个锁维护一个**持有计数**（hold count）
- 第一次获取锁时，计数器设为1
- 同一线程再次获取锁时，计数器递增
- 每次释放锁时，计数器递减
- 计数器为0时，锁被完全释放

2. 线程标识记录
- 锁内部保存当前持有线程的标识
- 通过 `Thread.currentThread()` 获取当前线程
- 只有持有线程才能重复获取锁

3. 与 `ObjectMonitor` 的关系
- `ObjectMonitor` 是 JVM 层面的监视器对象
- 每个 Java 对象都关联一个 `ObjectMonitor`
- `synchronized` 通过 `ObjectMonitor` 实现可重入性
- 监视器内部维护 `_count`（计数）和 `_owner`（持有者）字段

### `ObjectMonitor` 结构
```
ObjectMonitor {
    _header;       // 标记 word
    _count;        // 重入次数
    _waiters;      // 等待线程数
    _recursions;   // 重入计数
    _object;       // 关联对象
    _owner;        // 持有者线程
    _WaitSet;      // 等待集合
    _EntryList;    // 等待队列
}
```

## `Java` 中的可重入锁实现

- `synchronized` 关键字：隐式锁

## 可重入锁的特点

1. **避免死锁**: 同一线程可以重复获取已持有的锁
2. **计数机制**: 内部维护一个计数器记录锁被获取的次数
3. **线程持有**: 锁会记录当前持有线程的信息
4. **公平性选择**: 支持公平锁和非公平锁模式

## 可重入锁的优势

- 避免编程时因锁嵌套而导致的死锁问题
- 提高代码灵活性，支持递归调用等场景
- 更好的性能表现相比传统锁机制

## 使用注意事项

- 必须保证每次加锁都有对应的解锁操作
- 注意锁的粒度控制，避免长时间持有锁
- 在使用 `ReentrantLock` 时，确保在 `finally` 块中释放锁，必须做到一一配对

## 实际应用场景

- 递归算法中的同步控制
- 复杂业务逻辑中的分段加锁
- 需要精确控制锁行为的高性能场景
