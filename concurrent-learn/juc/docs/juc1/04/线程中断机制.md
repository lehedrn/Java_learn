# 线程中断机制

## 什么是中断机制

- 一个线程不应该由其他线程来强制中断或停止，而是应该由线程自己自行停止，自己来决定自己的命运，所以，`Thread.stop` ,`Thread.suspend` ,`Thread.resume` 都已经被废弃了
- 在 `Java` 中没有办法立即停止一条线程，然而停止线程却显得尤为重要，如取消一个耗时操作。因此，`Java` 提供了一种用于停止线程的协商机制----中断，也即中断标识协商机制
  - 中断只是一种协作协商机制，`Java` 没有给中断增加任何语法，中断的过程完全需要程序员自行实现。若要中断一个线程，你需要手动调用该线程 `interrupt` 方法，该方法也仅仅是将该线程对象的中断标识设置为 `true` ，接着你需要自己写代码不断检测当前线程的标识位，如果为 `true` ，表示别的线程请求这条线程中断，此时究竟应该做什么需要你自己写代码实现。
  - 每个线程对象都有一个中断标识位，用于表示线程是否被中断；该标识位为 `true` 表示中断，为 `false` 表示未中断；通过调用线程对象的 `interrupt` 方法将该线程的标识位设置为 `true` ；可以在别的线程中调用，也可以在自己的线程中调用。

因此，可以说**中断机制**是 `Java` 中一种协作式的线程中断方式，主要特点包括：

- 协作式：中断只是一个标志位，不会强制停止线程
- 基于标志位：通过设置线程的中断状态来实现
- 需要响应：被中断的线程需要主动检查中断状态并做出相应处理

## 中断的相关API方法

### `public void interrupt()`
- 用于请求中断线程，将目标线程的中断状态设置为true
- 如果目标线程正在等待(`wait`、`sleep`、`join`等阻塞状态)，则会抛出`InterruptedException`异常，并且中断状态会被清除
- 此方法可以由其他线程调用，也可以由线程自身调用

### `public static boolean interrupted()`
- 测试**当前正在执行的线程**是否已被中断, 并清除当前中断状态
- 这是一个静态方法，只能用于检查调用该方法的线程(当前线程)
- **重要特性**：调用此方法会清除当前线程的中断状态(将中断标识位重置为 `false`)
- 如果连续调用两次，第二次调用将返回 `false` (除非在两次调用之间再次设置了中断)

### `public boolean isInterrupted()`
- 测试**该线程实例**是否已被中断
- 这是一个实例方法，可以检查任意线程对象的中断状态
- **重要特性**：调用此方法**不会**清除线程的中断状态
- 可以多次调用而不会改变线程的中断状态

### 当前线程的中断表示为 `true` ，是不是线程就立刻停止

不会立刻停止，具体来说，当对一个线程，调用 `interrupt()` 方法时:

- 如果线程处于正常活动状态，那么会将该线程的中断标志设置为 `true`，仅此而已，被设置中断标志的线程将继续正常运行，不受影响，所以 `interrupt()` 方法并不能真正的中断线程，需要被调用的线程自己进行配合才行；对于不活动的线程则没有任何影响。 可以参见[InterruptDemo3.java](../../../src/main/java/com/coderlee/juc1/interrupt/InterruptDemo3.java)
- 如果线程处于阻塞状态（例如`sleep()`、`wait()`、`join()`等）中，在别的线程中调用线程对象的 `interrupt()` 方法，那么线程将立即退出被阻塞状态（ `interrupt` 状态也将被清除），并立即抛出一个 `InterruptedException` 异常。） 可以参见[InterruptDemo4.java](../../../src/main/java/com/coderlee/juc1/interrupt/InterruptDemo4.java)

### 谈谈对静态方法 `Thread.interrupted()` 的理解
- **作用**：`Thread.interrupted()` 是一个静态方法，用于测试**当前正在执行的线程**是否已被中断
- **关键特性**：
    - 仅能检查调用该方法的当前线程的中断状态
    - **会清除中断状态**：调用此方法后，会将当前线程的中断标识位重置为 `false`
    - 返回值为布尔类型：`true` 表示线程已被中断，`false` 表示未被中断
- **使用场景**：
    - 通常在需要检查并响应中断的代码块中使用
    - 特别适用于需要在中断发生后清除中断状态的场景
- **与 `isInterrupted()` 的区别**：
    - `isInterrupted()` 是实例方法，可检查任意线程对象的中断状态，且**不会清除**中断状态
    - `interrupted()` 是静态方法，只能检查当前线程，且**会清除**中断状态
- **注意事项**：
    - 由于会清除中断状态，连续调用两次 `interrupted()` 方法，第二次调用将返回 `false`（除非在两次调用之间再次设置了中断）
    - 在处理中断时需要谨慎使用，避免意外清除中断信号
