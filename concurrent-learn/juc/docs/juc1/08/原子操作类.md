# 原子操作类

## 1. 基本类型原子类

- `AtomicInterger` : 整型原子类
- `AtomicBoolean` : 布尔型原子类
- `AtomicLong` : 长整型原子类

### 常用 `API` 简介

```
public final int get() //获取当前的值
public final int getAndSet(int newValue)//获取当前的值，并设置新的值
public final int getAndIncrement()//获取当前的值，并自增
public final int getAndDecrement() //获取当前的值，并自减
public final int getAndAdd(int delta) //获取当前的值，并加上预期的值
boolean compareAndSet(int expect, int update) //如果输入的数值等于预期值，则以原子方式将该值设置为输入值（update）
public final void lazySet(int newValue)//最终设置为newValue,使用 lazySet 设置之后可能导致其他线程在之后的一小段时间内还是可以读到旧的值。
```

## 3. 引用类型原子类

- `AtomicReference` : 引用类型原子类
- `AtomicStampedReference` : 原子更新带有版本号的引用类型。该类将整数值与引用关联起来，可用于解决原子的更新数据和数据的版本号，可以解决使用 `CAS` 进行原子更新时可能出现的 `ABA` 问题。(解决修改过几次)
- `AtomicMarkableReference` : 原子更新带有标记的引用类型。该类将 `boolean` 标记与引用关联起来(解决是否修改过，它的定义就是将标记戳简化为 `true/false`，类似于一次性筷子)

### 常用 `API` 简介

```
// AtomicReference 常用方法
public final V get() // 获取当前引用
public final void set(V newValue) // 设置引用值
public final V getAndSet(V newValue) // 获取当前引用，并设置新的引用
public final boolean compareAndSet(V expect, V update) // 如果当前引用等于预期值，则以原子方式设置为新引用
public final void lazySet(V newValue) // 最终设置为新引用值

// AtomicStampedReference 特有方法
public final Pair<V> getPair() // 获取包含引用和时间戳的Pair对象
public final V get(int[] stampHolder) // 获取引用，同时将时间戳复制到stampHolder数组中
public final boolean compareAndSet(V expectedReference, V newReference, int expectedStamp, int newStamp) // 比较并设置引用和时间戳

// AtomicMarkableReference 特有方法
public final boolean isMarked() // 检查当前标记状态
public final boolean attemptMark(V expectedReference, boolean newMark) // 尝试标记引用
public final boolean compareAndSet(V expectedReference, V newReference, boolean expectedMark, boolean newMark) // 比较并设置引用和标记
```

## 4. 对象的属性修改原子类

- `AtomicIntegerFieldUpdater` : 原子更新对象中 `int` 类型字段的值
- `AtomicLongFieldUpdater` : 原子更新对象中 `Long` 类型字段的值
- `AtomicReferenceFieldUpdater` : 原子更新对象中引用类型字段的值

### 作用

对象的属性修改原子类用于对某个类的特定字段进行原子性操作，而无需将整个对象包装在原子引用中。这些更新器允许直接对对象的字段进行原子更新操作，提供了更细粒度的控制。直白的说，就是以一种线程安全的方式操作非线程安全对象内的某些字段。

主要优势：
- **内存效率**: 不需要创建额外的包装对象
- **直接访问**: 可以直接对目标对象的字段进行原子操作
- **灵活性**: 可以为不同的字段创建不同的更新器

### 常用 `API` 简介

```
// 创建更新器的方法（静态方法）
public static <U> AtomicIntegerFieldUpdater<U> newUpdater(Class<U> tclass, String fieldName)
public static <U> AtomicLongFieldUpdater<U> newUpdater(Class<U> tclass, String fieldName)
public static <U, W> AtomicReferenceFieldUpdater<U, W> newUpdater(Class<U> tclass, Class<W> vclass, String fieldName)

// 原子操作方法
public abstract boolean compareAndSet(T obj, int expect, int update) // 比较并设置int字段值
public abstract boolean compareAndSet(T obj, long expect, long update) // 比较并设置long字段值
public abstract boolean compareAndSet(T obj, V expect, V update) // 比较并设置引用字段值

public abstract int getAndSet(T obj, int newValue) // 获取并设置int字段值
public abstract long getAndSet(T obj, long newValue) // 获取并设置long字段值
public abstract V getAndSet(T obj, V newValue) // 获取并设置引用字段值

public abstract int getAndIncrement(T obj) // 原子性递增int字段值
public abstract long getAndIncrement(T obj) // 原子性递增long字段值

public abstract int getAndAdd(T obj, int delta) // 原子性增加int字段值
public abstract long getAndAdd(T obj, long delta) // 原子性增加long字段值
```

### 使用要求

1. **字段要求**: 目标字段必须是 `volatile` 类型，以确保可见性
2. **访问权限**: 字段通常需要是 `public` 或者在同一包内可访问
3. **类型安全**: 更新器只能用于与其创建时指定的类和字段类型相匹配的对象(因为对象的属性修改类型原子类都是抽象类，所以每次使用都必须使用静态方法 `newUpdater()` 创建一个更新器，并且需要设置想要更新的类和属性)

### `LongAddr` 源码剖析

`LongAdder` 是 `Java 8` 中引入的一个高性能的原子计数器，它是专门为高并发环境下的累加操作设计的。相比 `AtomicLong`，它在高并发场景下具有更好的性能表现。

#### `LongAdder` 的核心思想

`LongAdder` 的设计基于 **分段累加** 和 **延迟汇总** 的思想：

- 它内部维护了一个 `base` 变量和一个 `Cell[]` 数组（称为 cells）。
- 当没有竞争时，所有的累加操作都会直接作用于 `base` 变量上。
- 当检测到多线程竞争时（即 `CAS` 操作失败），会将累加任务分散到 `Cell[]` 数组中的不同元素中去执行，从而减少竞争。
- 最后需要获取总数时，将 `base` 和所有 `cells` 中的值相加即可得到最终结果。

#### `LongAdder` 的结构

以下是 `LongAdder` 的关键成员变量和方法：

```java
public class LongAdder extends Striped64 implements Serializable {
    private static final long serialVersionUID = 7249069246863182397L;

    public void add(long x) {
        Cell[] as; long b, v; int m; Cell a;
        if ((as = cells) != null || !casBase(b = base, b + x)) {
            boolean uncontended = true;
            if (as == null || (m = as.length - 1) < 0 ||
                (a = as[getProbe() & m]) == null ||
                !(uncontended = a.cas(v = a.value, v + x)))
                longAccumulate(x, null, uncontended);
        }
    }

    public long sum() {
        Cell[] as = cells;
        long sum = base;
        if (as != null) {
            for (Cell a : as)
                if (a != null)
                    sum += a.value;
        }
        return sum;
    }
}
```


#### `Striped64` 抽象基类

`Striped64` 是 `LongAdder` 的父类，提供了基本的分段机制和支持多线程并发访问的核心逻辑。

- 主要成员变量：

  - `transient volatile Cell[] cells;`：存储各个线程局部计数的数组。
  - `transient volatile long base;`：基础值，在无竞争的情况下使用。
  - `transient volatile int cellsBusy;`：用于创建或扩容 `cells` 数组时的自旋锁标志。

- `Cell` 类：

    每个 `Cell` 实例代表一个独立的计数单元，其结构非常简单：
    
    ```java
    @sun.misc.Contended static final class Cell {
        volatile long value;
        Cell(long x) { value = x; }
        final boolean cas(long cmp, long val) {
            return UNSAFE.compareAndSwapLong(this, valueOffset, cmp, val);
        }
        // ... 其他省略内容
    }
    ```

#### 工作流程详解

当调用 `add()` 方法进行累加时，具体步骤如下：
- **尝试更新 base**：
    - 如果当前不存在 `cells` 数组或者通过 CAS 成功地更新了 `base` 值，则直接完成累加；

- **发生竞争后的处理**：
    - 若发现存在竞争（即 CAS 失败），则进入下一步；
    - 判断是否已经初始化了 `cells` 数组，如果没有就进行初始化；
    - 计算当前线程应该使用的 cell 索引；
    - 尝试对该 cell 进行 CAS 更新；
    - 如果仍然失败，则调用 `longAccumulate` 方法进一步处理；

- **longAccumulate 方法的作用**：
    - 负责初始化 `cells` 数组；
    - 处理 cell 扩容；
    - 在必要时重新哈希线程 probe 值来分布到不同的 cell 上；

#### 性能优化点分析

- **避免热点**：通过将计数分散到多个 cell 中，大大降低了单一变量上的争用程度；
- **懒惰初始化**：只有真正遇到并发冲突才会分配 cells 数组，节省资源；
- **动态扩展**：根据实际并发情况自动调整 cells 数组大小；
- **缓存友好性**：利用 `@Contended` 注解防止伪共享问题，提高 CPU 缓存命中率；

#### 注意事项与限制

虽然 `LongAdder` 提供了出色的性能，但也有一些需要注意的地方：

- **不支持精确一致性读取**：由于采用了分段策略，因此 `sum()` 方法返回的是近似值，可能不是完全准确的结果；
- **不适合复杂运算**：只适用于简单的加法运算，无法像 `LongAccumulator` 那样支持任意二元操作；
- **内存占用较高**：在高并发情况下可能会消耗较多内存用于维护 cells 数组；

综上所述，`LongAdder` 是一种针对高并发累加场景专门优化过的高效工具类，特别适合那些不需要严格一致性的统计类应用场景。
