# **Stream API 中的收集与归约：collect / reduce / Collector 的设计与实践**

## 引言：归约与收集的区别

在 Java 8 中，Stream API 提供了强大的操作工具，用于处理集合数据。流的终止操作中，**归约（Reduction）** 和 **收集（Collection）** 是两个非常常见的概念，尤其是 `reduce()` 和 `collect()`，它们的本质有很大差异。虽然它们都可以将流中的多个元素聚合成一个结果，但适用的场景和实现方式有所不同。

### 1. 归约（Reduction）

归约操作通常是指将流中的元素**合并成单一的值**。例如，求和、求最大值、连接字符串等都属于归约操作。在归约操作中，所有的元素都会被按某种方式合并，而最终的结果是一个单一的值。归约可以通过 `reduce()` 来实现，它适用于**无状态的操作**，即每个元素的计算不依赖于其他元素的状态。

**例子**：

```java
Optional<Integer> sum = list.stream().reduce(Integer::sum);
```

在这个例子中，`reduce()` 将流中的所有整数累加，最终返回一个 `Optional<Integer>` 类型的结果。如果流为空，结果将是 `Optional.empty()`。

### 2. 收集（Collection）

与归约操作不同，收集操作是将流中的元素**转换成集合类型**，如 `List`、`Set` 或 `Map`。在收集过程中，结果不再是一个单一值，而是一个容器，存放流中的所有元素。最常见的收集操作是 `collect()`，它通常与 `Collector` 接口配合使用。`collect()` 适用于**有状态的归约**，能够将流中的元素收集到自定义的容器中，适合复杂的集合操作。

**例子**：

```java
List<Integer> list = stream.collect(Collectors.toList());
```

在这个例子中，`collect()` 将流中的所有元素收集到一个新的 `List` 中。

### 归约与收集的对比

* **归约**（`reduce()`）更适用于需要**单一输出**的操作，结果是一个单一的值，例如求和、求最小值等。
* **收集**（`collect()`）则适用于需要将元素**转存到容器**中的场景，比如将流中的元素收集成一个列表、集合或映射。

总结来说，`reduce()` 更倾向于“合并”或“缩减”流中的元素，而 `collect()` 则专注于“收集”流中的元素，并将其组织成一个容器。因此，选择使用 `reduce()` 还是 `collect()`，取决于你的最终目标是得到一个单一值还是一个容器。

## 二、`reduce` 三种重载的适用场景

在 Stream API 中，`reduce()` 是一种常用的归约操作。它将流中的元素按照指定的逻辑进行累积，最终得到一个结果。`reduce()` 有三种常见的重载方式，它们各自适用于不同的场景。理解每种重载的适用场景有助于选择正确的归约方法。

### 1️⃣ `reduce(BinaryOperator<T> accumulator)`

```java
Optional<Integer> sum = list.stream().reduce(Integer::sum);
```

**适用场景：**

* **无初始值的归约**：这种重载方法适用于不需要指定初始值的情况。`reduce()` 会从流的第一个元素开始应用归约操作。
* **返回 `Optional<T>`**：由于流可能为空，结果是一个 `Optional` 类型。如果流为空，返回 `Optional.empty()`，否则返回 `Optional` 包装的归约结果。

**示例解释：**
在这个例子中，`reduce()` 使用 `Integer::sum` 作为归约操作，将流中的所有整数进行求和。由于没有指定初始值，`reduce()` 会自动使用流中的第一个元素作为初始值，并逐步对其进行累加。

如果流为空，`reduce()` 将返回 `Optional.empty()`，因此需要通过 `Optional` 的方法来安全地访问结果。

**优点：**

* 简单直接，用于简单的无初始值归约操作。
* 适合处理返回类型为单一结果的归约问题，如求和、求最小值等。

### 2️⃣ `reduce(T identity, BinaryOperator<T> accumulator)`

```java
int sum = list.stream().reduce(0, Integer::sum);
```

**适用场景：**

* **有初始值的归约**：这种重载方法适用于需要指定初始值的场景。初始值作为归约操作的起点。
* **返回非 `Optional` 的结果**：由于指定了初始值，`reduce()` 的返回类型是直接的，不需要包装成 `Optional`，返回类型就是指定的类型 `T`。

**示例解释：**
在这个例子中，`reduce()` 使用 `0` 作为初始值，并且通过 `Integer::sum` 进行累加操作。初始值确保了无论流中是否存在元素，`reduce()` 都会返回一个有效的结果，避免了 `Optional.empty()` 的情况。

如果流为空，`reduce()` 将返回初始值 `0`，因此对于需要一个默认值的场景，这种形式非常有用。

**优点：**

* 提供初始值，确保结果始终有效，即使流为空。
* 适用于求和、计算积累结果等有默认初始值的场景。

### 3️⃣ `reduce(U identity, BiFunction<U, ? super T, U> accumulator, BinaryOperator<U> combiner)`

```java
String concatenated = list.stream().reduce("", (s, i) -> s + i, (s1, s2) -> s1 + s2);
```

**适用场景：**

* **并行流中的归约**：当使用并行流时，流的元素可能会被分割成多个子流处理，最终结果需要合并。这个重载方法提供了 `combiner()` 函数，帮助在多个子流之间合并结果。
* **更复杂的归约操作**：适用于更复杂的归约场景，可以定义自定义的合并操作，不仅仅是一个简单的二元操作。

**示例解释：**
在这个例子中，`reduce()` 使用空字符串 `""` 作为初始值，并通过 `s + i` 将每个字符串元素连接起来。`(s1, s2) -> s1 + s2` 是 `combiner` 函数，它定义了如何合并两个字符串的部分结果。在并行流中，每个线程会处理一部分数据，`combiner` 用来合并线程之间的部分结果。

这种方式在并行流中尤为重要，它能够保证线程安全地合并多个部分结果。

**优点：**

* 适用于并行流，支持合并操作。
* 可以实现更复杂的归约逻辑，如合并字符串、合并自定义对象等。
* 通过 `combiner` 保证了线程安全，适合用于多线程操作。

### 小结：

* **`reduce(BinaryOperator<T> accumulator)`**：适用于无初始值的归约，结果是 `Optional<T>`，适合处理简单的归约操作。
* **`reduce(T identity, BinaryOperator<T> accumulator)`**：适用于有初始值的归约，确保无论流是否为空都能返回有效结果，结果类型为 `T`。
* **`reduce(U identity, BiFunction<U, ? super T, U> accumulator, BinaryOperator<U> combiner)`**：适用于并行流，能够在多个线程中合并计算结果，支持更复杂的归约逻辑。

根据不同的归约需求，可以选择不同的 `reduce()` 重载方式。通过合理使用这三种方法，能够灵活地处理流中元素的聚合与合并操作。

## 三、为什么大多数时候用 `collect()`？

`collect()` 是 Stream API 中非常常用的终止操作之一，它的核心功能是将流中的元素**收集到某个容器中**，例如 `List`、`Set` 或 `Map`。与 `reduce()` 不同，`collect()` 支持复杂的收集需求，并且能够处理有状态的操作。由于其强大的灵活性和广泛的适用场景，大多数情况下我们会选择 `collect()` 而不是 `reduce()`。

### 1. 强大的灵活性

`collect()` 最吸引人的特点之一就是其**灵活性**。它不仅能将元素收集到简单的集合中（如 `List` 或 `Set`），还可以用来执行更复杂的归约操作。例如，我们可以将流中的元素分组、分区，甚至根据条件筛选后收集到不同的容器。

`collect()` 是通过 `Collector` 接口来实现的，`Collector` 提供了丰富的 API，使得我们能够灵活地定义如何将流中的元素收集到目标容器中。常见的收集操作，如 `toList()`、`toSet()`、`toMap()` 都是 `Collector` 的实现。

**示例：**

```java
// 将流中的元素收集到 List
List<Integer> list = stream.collect(Collectors.toList());
```

**示例：**

```java
// 将流中的元素分组
Map<Integer, List<String>> grouped = stream.collect(Collectors.groupingBy(String::length));
```

### 2. 支持有状态的归约

`collect()` 与 `reduce()` 的最大区别在于它支持**有状态的归约**。`reduce()` 是无状态的，它的结果是通过对每个元素的逐步累积而得出的，适用于简单的合并操作。而 `collect()` 更适合做**复杂的有状态归约操作**，例如：

* 将流中的元素按照某个规则分组。
* 将流中的元素进行分区。
* 根据条件筛选元素，收集到不同的容器。

有状态操作的一个典型场景就是将流中的元素根据某些条件分组，`collect()` 提供了非常强大的功能来处理这些需求。

**示例：**

```java
// 按照字符串的长度分组
Map<Integer, List<String>> groupedByLength = stream.collect(Collectors.groupingBy(String::length));
```

在这个例子中，`groupingBy()` 会根据每个字符串的长度将流中的元素分组，返回一个 `Map<Integer, List<String>>`，其中 `Integer` 是字符串的长度，`List<String>` 是具有相同长度的字符串集合。

### 3. 扩展性

由于 `Collector` 接口的设计，`collect()` 提供了极强的**扩展性**。你可以通过实现自定义的 `Collector`，从而完成各种特定需求的收集操作。比如，你可以创建线程安全的 `Collector`，或者定义自己的容器类型来收集元素。

通过 `Collector.of()` 方法，你可以非常灵活地定义收集器的行为，包括初始化容器、添加元素、合并容器以及最终结果的转换。

**示例：**

```java
Collector<String, StringBuilder, String> joiningCollector = Collector.of(
    StringBuilder::new,           // supplier：创建容器
    StringBuilder::append,        // accumulator：添加元素
    StringBuilder::append,        // combiner：合并结果
    StringBuilder::toString       // finisher：最终转换
);

String result = stream.collect(joiningCollector);
```

在这个例子中，使用 `Collector.of()` 自定义了一个 `Collector`，它将流中的字符串元素连接起来，最后返回一个拼接后的字符串。

### 4. 适用范围广

`collect()` 适用于各种复杂的集合操作，它不仅能够满足基本的收集需求，还能处理像**分组**、**分区**、**映射**等复杂操作。这些操作通常是通过 `Collector` 接口的预定义方法实现的，如 `groupingBy()`、`partitioningBy()`、`toMap()` 等。与 `reduce()` 只能进行单一值归约不同，`collect()` 能够应对各种场景，尤其是当你需要将流中的元素收集到复杂的容器中时，`collect()` 是不可或缺的。

**示例：**

```java
// 分区：将流中的元素根据某个条件分成两部分
Map<Boolean, List<String>> partitioned = stream.collect(Collectors.partitioningBy(s -> s.length() > 3));
```

### 5. 线程安全的并行处理

`collect()` 还能够高效地处理并行流操作。通过合理设计 `Collector`，你可以确保并行流中的元素在多个线程间正确合并。例如，`toList()` 和 `toSet()` 都是并行安全的，可以直接在并行流中使用。

对于并行流，`Collector` 需要支持**合并操作**，这通过 `combiner()` 来实现。`collect()` 使得并行操作更容易，因为它能够高效地将多个线程中的结果合并到一起，确保正确性和性能。

**示例：**

```java
List<Integer> result = parallelStream.collect(Collectors.toList());
```

### 小结

大多数情况下我们选择使用 `collect()` 而不是 `reduce()`，因为它具有更强的灵活性、扩展性和适应性，特别适用于复杂的收集需求。通过 `collect()`，我们可以轻松地将流中的元素收集到容器中，并实现分组、分区等有状态的操作。此外，`collect()` 还能支持并行流操作，进一步提升性能。因此，它是处理流数据时更常用的操作。

## 四、`Collector` 接口的四个核心方法

`Collector` 接口是 `collect()` 方法的核心组成部分，它定义了如何将流中的元素收集到一个容器中。`Collector` 提供了四个核心方法，分别用于创建容器、将元素添加到容器中、合并容器和完成收集操作。理解这四个方法的作用和用法，对于自定义收集器非常重要。

### 1️⃣ `supplier()`

```java
public Supplier<R> supplier();
```

* **作用**：`supplier()` 方法提供一个结果容器（即收集流元素的目标容器）。这个容器通常是一个空的集合，例如 `ArrayList`、`HashSet` 或者其他自定义类型。

* **示例**：在 `Collectors.toList()` 中，`supplier()` 会返回一个新的 `ArrayList`。

**例子**：

```java
Collector<String, List<String>, List<String>> toListCollector = Collector.of(
    ArrayList::new,  // supplier：创建一个新的 ArrayList
    List::add,       // accumulator：将元素添加到 List 中
    (left, right) -> { left.addAll(right); return left; }, // combiner
    List::new        // finisher
);
```

在这个例子中，`supplier()` 方法返回一个新的 `ArrayList`，用于收集流中的元素。

### 2️⃣ `accumulator()`

```java
public BiConsumer<R, T> accumulator();
```

* **作用**：`accumulator()` 方法定义了如何将流中的每个元素添加到结果容器中。它返回一个 `BiConsumer`，该消费者接收当前容器和流中的一个元素，将该元素添加到容器中。

* **示例**：在 `Collectors.toList()` 中，`accumulator()` 会调用 `List.add()` 方法，将元素添加到 `List` 中。

**例子**：

```java
Collector<String, StringBuilder, String> joiningCollector = Collector.of(
    StringBuilder::new,  // supplier
    StringBuilder::append,  // accumulator
    StringBuilder::append,  // combiner
    StringBuilder::toString  // finisher
);
```

在这个例子中，`accumulator()` 定义了如何将字符串元素拼接到 `StringBuilder` 中。

### 3️⃣ `combiner()`

```java
public BinaryOperator<R> combiner();
```

* **作用**：`combiner()` 方法用于在并行流中合并多个子流的结果。当流被拆分成多个子流并行执行时，每个子流都有自己的中间结果，`combiner()` 方法定义了如何将这些子流的结果合并成最终的结果。

* **示例**：在 `Collectors.toList()` 中，`combiner()` 会将两个 `List` 合并成一个。

**例子**：

```java
Collector<String, StringBuilder, String> joiningCollector = Collector.of(
    StringBuilder::new, 
    StringBuilder::append, 
    StringBuilder::append,  // 合并两个 StringBuilder
    StringBuilder::toString 
);
```

在这个例子中，`combiner()` 定义了如何将两个 `StringBuilder` 合并成一个。

### 4️⃣ `finisher()`

```java
public Function<R, A> finisher();
```

* **作用**：`finisher()` 方法是收集器的最后一步，它允许对中间结果进行最终的转换操作。它接收收集到的结果并将其转换为最终的结果。默认情况下，`finisher()` 返回 `identity()`，即不做任何转换。

* **示例**：在 `Collectors.toList()` 中，`finisher()` 直接返回结果容器（`List`）。在其他复杂的收集器中，`finisher()` 可以执行额外的转换，比如将一个 `StringBuilder` 转换为最终的 `String`。

**例子**：

```java
Collector<String, StringBuilder, String> joiningCollector = Collector.of(
    StringBuilder::new, 
    StringBuilder::append, 
    StringBuilder::append, 
    StringBuilder::toString  // finisher：将 StringBuilder 转换为 String
);
```

在这个例子中，`finisher()` 将 `StringBuilder` 转换为最终的 `String`。

### 小结：

`Collector` 接口的四个核心方法：

* `supplier()`：提供一个新的容器。
* `accumulator()`：定义如何将流中的元素添加到容器中。
* `combiner()`：定义如何合并多个容器中的结果。
* `finisher()`：定义如何将中间结果转换为最终结果。

通过这四个方法，我们可以灵活地自定义如何收集流中的元素，创建各种收集操作，满足不同的需求。

## 五、`Characteristics` 的真实作用

在 `Collector` 接口中，`Characteristics` 是一个枚举类型，用于标识一个收集器的特性。它的作用主要体现在 **并行流** 的优化上，通过 `Characteristics` 可以告诉 Stream API 收集器的行为，从而帮助优化流的执行，尤其是在并行流的环境下。合理地使用 `Characteristics` 可以提升性能，减少不必要的同步和排序操作。

### 1️⃣ `CONCURRENT`

#### **作用：支持并行操作**

`CONCURRENT` 表示该收集器可以在并行流中安全地执行。在并行流中，Stream 会将数据分成多个子流进行并行处理，因此某些收集器需要能够处理线程安全的问题，`CONCURRENT` 标识就意味着收集器在并行流中可以安全地执行，而不需要额外的同步控制。

如果收集器被标记为 `CONCURRENT`，Stream API 会根据该特性进行优化，避免在并行流中使用不支持并行的收集器。例如，`Set` 类型的收集器通常是无序的，因此可以在并行流中进行并行化操作，而无需担心线程之间的数据竞争问题。

#### **示例**：

```java
Stream<Integer> stream = Stream.of(1, 2, 3, 4, 5);
Set<Integer> set = stream.parallel().collect(Collectors.toSet());  // CONCURRENT
```

在此示例中，`Collectors.toSet()` 收集器被标记为 `CONCURRENT`，因此它能够在并行流中安全地执行，多个线程可以同时处理不同的部分数据，并合并结果。

**为什么 `CONCURRENT` 适用于 `Set` 和 `List`：**

* `Set` 和 `List` 都是容器类型，但 `Set` 的实现（如 `HashSet`）通常不关心元素的顺序，因此可以在并行流中不考虑顺序地将元素添加进去，直接并行操作。
* `List` 收集器通常是顺序敏感的，如果希望使用并行流操作 `List`，需要保证其线程安全性（如 `CopyOnWriteArrayList`）。

#### **性能优势：**

* 并行流中的操作可以大大提高处理大数据量时的性能，特别是当操作可以分开执行时。
* 标记为 `CONCURRENT` 的收集器，不会发生线程竞争，因此并行执行时不会有额外的同步开销。

### 2️⃣ `UNORDERED`

#### **作用：无序操作**

`UNORDERED` 表示该收集器**不关心元素的顺序**。当收集器被标记为 `UNORDERED` 时，Stream API 在并行流处理过程中，不需要保持流中元素的顺序。这样做的好处是，能够显著提高并行流的执行效率，因为操作不再受到顺序的限制，可以更高效地进行拆分和合并操作。

通常，`Set` 类型的收集器是 `UNORDERED` 的，因为 `Set` 的特性本身就不保证元素的顺序。而像 `List` 类型的收集器则是有序的，因此不会标记为 `UNORDERED`。

#### **示例**：

```java
Stream<Integer> stream = Stream.of(1, 2, 3, 4, 5);
Set<Integer> set = stream.parallel().collect(Collectors.toSet());  // UNORDERED
```

在此示例中，`Collectors.toSet()` 返回一个无序的 `Set`，因此可以在并行流中无需关心顺序地进行并行操作。

#### **性能优势：**

* 并行流的优化，`UNORDERED` 标识使得元素的顺序不再需要保证，这大大降低了在合并阶段需要的同步操作和排序成本。
* 处理大量数据时，减少了顺序保证所带来的性能开销，可以充分利用并行流的优势，提升执行速度。

#### **注意：**

* 如果你需要保留流中元素的顺序，则不应使用 `UNORDERED` 标识。
* 适合于 `Set`、`HashSet` 等不关心顺序的集合类型，而不适用于 `List` 和 `Queue` 类型。

### 3️⃣ `IDENTITY_FINISH`

#### **作用：收集器本身即为最终结果**

`IDENTITY_FINISH` 表示收集器的最终处理步骤是“身份函数”，即收集器本身的结果就已经是最终的结果，不需要进一步的转换操作。在这种情况下，`finisher()` 方法返回 `identity()`，即不进行任何转换或处理，直接返回收集的容器或结果。

#### **示例**：

```java
Stream<Integer> stream = Stream.of(1, 2, 3, 4, 5);
List<Integer> list = stream.collect(Collectors.toList());  // IDENTITY_FINISH
```

在这个例子中，`Collectors.toList()` 是一个没有最终转换操作的收集器，`finisher()` 方法返回 `identity()`，即返回一个已经填充好的 `List`。结果直接就是收集的容器，无需做任何其他转换。

#### **性能优势：**

* **优化并行流性能**：并行流中的收集操作可以不需要额外的步骤，直接返回容器类型，避免了不必要的处理开销，提升了效率。
* **简化收集过程**：当收集器不需要进行额外的转换时，`IDENTITY_FINISH` 使得整个收集过程更加简洁和高效。

#### **示例扩展**：

```java
// 使用 StringBuilder 拼接字符串
Collector<String, StringBuilder, String> joiningCollector = Collector.of(
    StringBuilder::new,
    StringBuilder::append,
    StringBuilder::append,
    StringBuilder::toString   // 非 IDENTITY_FINISH
);
```

相比于上面的 `Collectors.toList()`，此示例中的收集器需要对 `StringBuilder` 进行 `toString()` 转换，因此没有 `IDENTITY_FINISH`。

### 4️⃣ `CONCURRENT` 与 `UNORDERED` 的联合使用

通常，`CONCURRENT` 和 `UNORDERED` 会一起使用，尤其是在那些不关心顺序且支持并行处理的收集器中。比如 `toSet()` 和 `toList()` 等，它们都被标记为这两个特性，因为在并行流中处理数据时，它们可以并行执行且不需要保证元素的顺序。

#### **示例**：

```java
Stream<Integer> stream = Stream.of(1, 2, 3, 4, 5);
Set<Integer> set = stream.parallel().collect(Collectors.toSet());  // CONCURRENT + UNORDERED
```

### 小结：

`Characteristics` 的作用在于告诉 Stream API 如何在并行流中优化收集过程，具体包括：

* **`CONCURRENT`**：表示收集器在并行流中是线程安全的，可以并行处理流中的元素而无需额外的同步。
* **`UNORDERED`**：表示收集器不关心元素的顺序，适用于那些无序集合（如 `Set`），可以在并行流中提高性能。
* **`IDENTITY_FINISH`**：表示收集器的结果容器本身就是最终结果，无需额外的转换步骤。

合理地使用这些特性，能够显著提高流操作的效率，特别是在并行流的场景下。它们允许 Stream API 优化数据的拆分、合并、同步等操作，确保并行流在处理大数据量时能够高效地执行。

## 六、进阶：mutable reduction 的本质

### **mutable reduction：收集器的结果是可变的**

在流的归约操作中，有一种特殊的归约方式称为 **mutable reduction**，即收集器的结果容器是**可变的**。这意味着流中的元素在被归约过程中会逐渐修改容器的内容，而不是生成一个全新的对象。这与无状态操作（例如 `reduce()`）不同，后者每次都基于当前元素和一个初始值来生成新的中间结果。

#### **为什么要使用 mutable reduction？**

1. **提高性能**：mutable reduction 允许流操作在归约过程中直接修改已有容器，而不是每次都生成一个新的容器。这样可以减少内存分配和复制开销，提高性能。
2. **灵活性**：通过可变的结果容器，可以在归约过程中灵活地进行更复杂的操作，比如分组、分区、排序等。

例如，假设你需要将流中的所有元素收集到一个 `Map` 中，并按照某种规则进行分组，你可以使用一个可变的容器（例如 `HashMap`），在流的每个元素上不断修改该容器。

#### **示例**：

```java
Map<Integer, List<String>> groupedByLength = stream.collect(
    Collectors.groupingBy(String::length)
);
```

在这个例子中，`groupingBy` 会使用一个可变的 `Map`，在流的每个元素上进行操作，最终返回一个分组好的 `Map`。容器 `Map` 会随着流操作逐渐修改，而不是每次都重新生成一个新 `Map`。

### **并行流中的 mutable reduction：如何避免数据竞争，确保并行计算的正确性**

并行流中的 mutable reduction 更具挑战性，因为多个线程可能同时访问和修改相同的容器。如果没有适当的同步机制，就可能发生数据竞争，导致最终结果不正确。为了解决这个问题，需要合理设计线程安全的收集器，确保并行流操作中的数据一致性。

在并行流中，Stream 会将数据拆分成多个子流，并分配给不同的线程进行处理。每个线程都会创建自己的本地容器来暂时存储中间结果，然后通过合并操作将各个线程的结果合并成最终结果。为了避免数据竞争，我们通常依赖于收集器的 **`combiner()`** 方法来处理线程间的合并操作。

#### **如何避免数据竞争？**

1. **无共享状态**：每个线程使用独立的本地容器，这样就避免了对同一个容器的并发修改。
2. **合并操作（`combiner()`）**：在多个线程处理完自己的任务后，`combiner()` 会负责合并不同线程的局部结果。合并操作需要是无副作用的，即合并后的结果不会影响原始容器的状态，避免出现数据竞争。
3. **线程安全的容器**：对于某些特定的操作，如并行累加操作，可以使用线程安全的容器（例如 `ConcurrentHashMap`、`CopyOnWriteArrayList` 等），以确保线程间的安全操作。

#### **示例**：并行流中的 mutable reduction

```java
Map<Integer, List<String>> result = stream.parallel().collect(
    Collectors.groupingBy(
        String::length,
        Collectors.mapping(String::toUpperCase, Collectors.toList())
    )
);
```

在这个例子中，`Collectors.groupingBy` 和 `Collectors.mapping` 都涉及 mutable reduction。每个线程会处理自己部分的数据，并将结果存入本地容器。最后，`combiner()` 会将不同线程中的局部结果合并成最终的 `Map`。

## 七、`Collector` 与并行流的关系

### **如何设计一个线程安全的 `Collector` 来支持并行流**

设计一个线程安全的 `Collector` 来支持并行流，关键在于确保每个线程都能独立地进行操作，避免线程间的数据冲突或竞争。通常，线程安全的 `Collector` 需要满足以下几个条件：

1. **无共享状态**：每个线程都需要有自己的本地容器（即本地副本）。通过避免共享状态，确保不同线程之间不会产生冲突。
2. **合并操作（`combiner()`）**：如果流是并行处理的，`combiner()` 方法会负责合并来自不同线程的局部结果。设计时需要保证合并操作是线程安全的，并且能够正确合并不同线程的中间结果。
3. **不依赖顺序**：并行流的操作通常不关心元素的顺序，因此收集器设计时应避免依赖顺序的操作，确保并行计算的高效性。

#### **设计一个线程安全的 `Collector` 的步骤：**

* **创建本地容器**：在 `supplier()` 方法中，返回一个线程本地的容器。每个线程将独立地使用这个容器来收集流中的元素。
* **定义累加操作**：在 `accumulator()` 方法中，定义如何将每个元素累加到本地容器中。每个线程在自己的容器上进行操作，不会发生线程安全问题。
* **合并本地结果**：在 `combiner()` 方法中，定义如何合并不同线程的本地容器。合并操作需要是线程安全的，并能够正确地将多个容器合并成一个最终容器。

#### **示例：设计一个线程安全的 `Collector`**

假设我们要设计一个 `Collector`，用于并行计算流中的元素之和，并且支持线程安全：

```java
public class ThreadSafeSumCollector implements Collector<Integer, AtomicInteger, Integer> {

    @Override
    public Supplier<AtomicInteger> supplier() {
        // 每个线程有自己的 AtomicInteger 用于并行计算
        return AtomicInteger::new;
    }

    @Override
    public BiConsumer<AtomicInteger, Integer> accumulator() {
        // 将每个元素累加到 AtomicInteger 中
        return AtomicInteger::addAndGet;
    }

    @Override
    public BinaryOperator<AtomicInteger> combiner() {
        // 合并两个 AtomicInteger 的值
        return (a, b) -> {
            a.addAndGet(b.get());
            return a;
        };
    }

    @Override
    public Function<AtomicInteger, Integer> finisher() {
        // 最终结果转换，返回 AtomicInteger 的值
        return AtomicInteger::get;
    }

    @Override
    public Set<Characteristics> characteristics() {
        return EnumSet.of(Characteristics.CONCURRENT, Characteristics.IDENTITY_FINISH);
    }
}
```

在这个例子中，`AtomicInteger` 用于线程安全地累加每个元素的值。每个线程将自己部分的元素累加到自己的 `AtomicInteger` 中，最后通过 `combiner()` 将不同线程的结果合并。

### **`combiner()` 如何在并行流中合并不同线程的结果**

在并行流中，流的元素会被拆分成多个子流，分配给不同的线程进行处理。每个线程都会生成自己的中间结果。当所有线程完成计算后，`combiner()` 方法会被用来合并这些局部结果。

**合并操作的关键点：**

1. **无副作用**：合并操作必须是无副作用的，即合并后的结果不会影响原始容器。合并过程必须确保并发安全，不会破坏数据的正确性。
2. **高效性**：合并操作需要高效地将两个局部结果合并为一个，尽量减少不必要的计算和同步。

#### **示例：`combiner()` 合并操作**

```java
BinaryOperator<AtomicInteger> combiner = (a, b) -> {
    a.addAndGet(b.get());
    return a;
};
```

在此示例中，`combiner()` 会将两个 `AtomicInteger` 合并，通过 `addAndGet()` 将两个 `AtomicInteger` 的值累加到一个容器中，确保线程安全。

### 小结：

* **mutable reduction** 的本质在于收集器的结果是可变的，使得在流操作中可以不断地修改结果容器。对于并行流中的 mutable reduction，关键在于通过线程安全的合并操作（`combiner()`）确保数据一致性，避免数据竞争。
* **设计线程安全的 `Collector`** 时，确保每个线程拥有独立的本地容器，利用 `combiner()` 高效地合并各线程的结果。
* **`combiner()`** 在并行流中起到了至关重要的作用，能够正确地合并不同线程计算出来的局部结果，确保并行计算的正确性和高效性。
