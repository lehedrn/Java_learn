# 第 5 篇：高级应用、最佳实践与迁移指南

## 引言：从 API 学习到工程落地

在前几篇中，我们已经系统性地介绍了 Java 8 新时间日期 API 的核心模型：

* 不可变的时间对象（`LocalDate / LocalDateTime / Instant`）
* 时区与偏移（`ZoneId / ZonedDateTime`）
* 时间间隔与周期（`Duration / Period`）
* 格式化、解析与查询（`DateTimeFormatter / TemporalAdjuster / TemporalQuery`）

但真正的问题是：

> **在真实项目中，这套 API 应该如何落地？**
>
> 如何与 JDBC、Spring 等基础设施集成？
> 如何迁移遗留系统中的 `Date / Calendar`？
> 如何写出“可测试、可维护、性能可控”的时间代码？

这一篇，我们从 **工程实践视角** 给出答案。

## 一、高级主题一：与其他 API 的集成

### 1️⃣ 与 JDBC 的集成（Timestamp / Date）

在数据库层，时间通常以 `TIMESTAMP / DATE` 存储，对应旧 API：

* `java.sql.Date`
* `java.sql.Timestamp`

Java 8 提供了**无缝桥接方式**。

#### ✔ 推荐映射关系

| 数据库类型                    | Java 8 类型                        |
| ------------------------ | -------------------------------- |
| DATE                     | `LocalDate`                      |
| TIMESTAMP                | `LocalDateTime`                  |
| TIMESTAMP WITH TIME ZONE | `OffsetDateTime / ZonedDateTime` |

#### 示例：Timestamp ↔ LocalDateTime

```java
Timestamp timestamp = new Timestamp(System.currentTimeMillis());

// JDBC → Java 8
LocalDateTime ldt = timestamp.toLocalDateTime();

// Java 8 → JDBC
Timestamp newTs = Timestamp.valueOf(ldt);
```

📌 **实践建议**：

* DAO 层就完成转换
* **不要**让 `java.util.Date` 渗透到业务层

---

### 2️⃣ Spring Framework 的原生支持

Spring 对 Java 8 时间 API 是**一等公民支持**。

#### JSON 序列化（Jackson）

```java
@Bean
public ObjectMapper objectMapper() {
    ObjectMapper mapper = new ObjectMapper();
    mapper.registerModule(new JavaTimeModule());
    return mapper;
}
```

这样即可直接支持：

```json
"createTime": "2025-12-26T18:30:00"
```

#### Spring MVC 参数绑定

```java
@GetMapping("/order")
public String query(
        @RequestParam
        @DateTimeFormat(pattern = "yyyy-MM-dd")
        LocalDate date) {
    return "OK";
}
```

## 二、高级主题二：Clock —— 时间的“依赖反转”

### 为什么需要 `Clock`？

`LocalDateTime.now()` 最大的问题是：

> **不可测试**

Java 8 提供了 `Clock`，用于**控制时间来源**。

---

### 固定时间示例（单元测试神器）

```java
Clock fixedClock = Clock.fixed(
        Instant.parse("2025-12-26T10:00:00Z"),
        ZoneId.of("UTC")
);

LocalDateTime now = LocalDateTime.now(fixedClock);
```

📌 **最佳实践**：

* 在业务类中 **注入 Clock**
* 测试时替换为 `fixedClock`

这是一种非常典型的 **时间维度的依赖反转**。

## 三、Year / Month 等辅助类：别再用 int 了

### 1️⃣ Year / Month 的价值

```java
Year year = Year.of(2025);
Month month = Month.DECEMBER;
```

它们解决的问题是：

* 消除魔法数字
* 表达“时间语义”

---

### 2️⃣ 年 / 季度计算示例

```java
Month month = LocalDate.now().getMonth();

int quarter = (month.getValue() - 1) / 3 + 1;

log.info("Current quarter: Q{}", quarter);
```

📌 **推荐场景**：

* 财务系统
* 报表统计
* 账期 / 结算周期

## 四、最佳实践一：旧代码迁移指南

### 迁移步骤（强烈推荐顺序）

#### Step 1：边界先迁移

* Controller / RPC / DTO
* 数据库映射层

#### Step 2：业务逻辑层全面替换

* `Date` → `LocalDateTime`
* `Calendar` → `ZonedDateTime`

#### Step 3：工具类清理

* 删除 `SimpleDateFormat`
* 引入 `DateTimeFormatter`

---

### 旧 → 新 API 对照表

| 旧 API            | 新 API             |
| ---------------- | ----------------- |
| Date             | Instant           |
| Calendar         | ZonedDateTime     |
| SimpleDateFormat | DateTimeFormatter |

---

## 五、异常与边界问题（真实系统必须面对）

### 1️⃣ 闰秒问题

Java **不支持闰秒**，表现为：

> 时间连续递增，不会出现 `23:59:60`

📌 对策：

* 金融 / 天文系统：依赖 NTP / 外部时间源
* 普通业务系统：**可忽略**

---

### 2️⃣ 时区规则变化

时区规则并非静态（政治因素）。

📌 建议：

* **永远使用 `ZoneId`**
* 定期升级 JDK（时区数据随 JDK 更新）

---

## 六、性能最佳实践

### ✔ 推荐

```java
private static final DateTimeFormatter FORMATTER =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
```

原因：

* `DateTimeFormatter` 不可变
* 线程安全
* 可缓存

---

### ❌ 避免

* 频繁 `Date ↔ LocalDateTime` 转换
* 在循环中创建格式器

## 七、完整实战案例：预约系统（简化版）

### 场景描述

* 用户选择本地时间预约
* 系统统一存储为 UTC
* 支持跨时区展示

---

### 核心模型

```java
class Appointment {
    private Instant startTime;
    private ZoneId userZone;
}
```

---

### 创建预约

```java
public Appointment create(
        LocalDateTime localTime,
        ZoneId userZone) {

    Instant instant =
            localTime.atZone(userZone).toInstant();

    Appointment appt = new Appointment();
    appt.setStartTime(instant);
    appt.setUserZone(userZone);
    return appt;
}
```

---

### 展示预约时间

```java
public String display(Appointment appt) {
    ZonedDateTime userTime =
            appt.getStartTime().atZone(appt.getUserZone());

    return userTime.format(
            DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm"));
}
```

## 结尾总结：一套“工程级”的时间体系

Java 8 新时间日期 API 的真正价值，不在于“API 更好看”，而在于：

* 不可变性 → 天然线程安全
* 明确建模 → 消除歧义
* 可测试性 → 支持 `Clock`
* 工程友好 → 与生态深度集成

> **时间不是工具问题，而是建模问题。**

如果你在项目中正确使用这套 API，
你会发现：
**时间相关 Bug，会明显减少一个数量级。**
