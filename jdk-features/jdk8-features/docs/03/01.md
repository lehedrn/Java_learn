# **方法引用详解与实战**

Java 8 带来了 Lambda 表达式和函数式接口，使 Java 的编程风格更接近函数式语言，代码更加简洁和易读。在学习 Lambda 的过程中，你可能会发现很多 Lambda 只是简单地调用已有的方法，这时候就可以用 **方法引用（Method References）** 来替代 Lambda，让代码更清晰。本文将从原理、类型、示例到性能优化，全面解析方法引用，并提供实践建议。

---

## **1️⃣ 前言：为什么要用方法引用**

Lambda 表达式的出现，让我们可以用函数式接口传递行为：

```java
List<String> list = Arrays.asList("a", "b", "c");
list.forEach(s -> System.out.println(s));
```

上面这段代码其实只是调用了 `System.out.println` 方法。Lambda 只是包装了一层逻辑，而方法引用可以直接引用已有方法：

```java
list.forEach(System.out::println);
```

相比 Lambda，方法引用的优势：

* **更简洁**：减少模板代码
* **更可读**：直接说明调用的方法
* **可维护性高**：方法名本身就是逻辑

---

## **2️⃣ 方法引用概念**

* **定义**：方法引用是 Lambda 表达式的一种简写形式，用于直接引用已有的方法或对象的实例方法。
* **本质**：它仍然是函数式接口的实例，只是语法更简洁。
* **核心思想**：不改变逻辑，只是把 Lambda 中的“调用动作”直接抽出来引用。

> 可以把方法引用理解为 Lambda 的语法糖，它让代码更干净，同时保持性能不变。

---

## **3️⃣ 方法引用的类型与语法**

Java 8 提供了三种主要方法引用类型：

| 类型          | 语法                          | 示例                    | 注意事项                                         |
| ----------- | --------------------------- | --------------------- | -------------------------------------------- |
| **对象的实例方法** | `obj::instanceMethod`       | `System.out::println` | Lambda 对应 `(x) -> obj.instanceMethod(x)`     |
| **类的静态方法**  | `ClassName::staticMethod`   | `Integer::parseInt`   | Lambda 对应 `(x) -> ClassName.staticMethod(x)` |
| **类的实例方法**  | `ClassName::instanceMethod` | `String::equals`      | 第一个参数作为调用者，后续参数作为方法参数                        |

### **类实例方法引用解析**

```java
BiPredicate<String, String> bp = String::equals;
boolean flag = bp.test("a", "b"); // 相当于 "a".equals("b")
```

* 第一个参数 `"a"` 成为调用者
* 第二个参数 `"b"` 成为方法参数
* 这是类实例方法引用最容易混淆的地方，需要特别注意参数流向。

---

## **4️⃣ 方法引用示例解析**

### **对象实例方法引用**

```java
List<String> list = Arrays.asList("a", "b", "c");
list.forEach(System.out::println);
```

* Lambda 对应写法：`list.forEach(s -> System.out.println(s));`
* 方法引用更直接，表明调用的是 `System.out.println` 方法。

### **类静态方法引用**

```java
Function<String, Integer> func = Integer::parseInt;
Integer result = func.apply("123"); // 123
```

* 相当于 Lambda：`x -> Integer.parseInt(x)`
* 静态方法引用通常用于工具类方法或工厂方法。

### **类实例方法引用**

```java
BiPredicate<String, String> bp = String::equals;
boolean isEqual = bp.test("abc", "abc"); // true
```

* 第一个参数 `"abc"` 是调用者，第二个参数 `"abc"` 是方法参数
* 对比 Lambda：`(s1, s2) -> s1.equals(s2)`

> 💡 建议读者画箭头标注参数流向，帮助理解类实例方法引用。

---

## **5️⃣ 方法引用的优势与使用场景**

### **优势**

* 代码更简洁
* 可读性更高
* 避免重复 Lambda 模板代码

### **典型使用场景**

* Lambda 内仅调用已有方法时
* Stream API 中的 map、forEach、filter 等方法

```java
List<String> words = Arrays.asList("apple", "banana", "orange");
words.stream()
     .map(String::toUpperCase)
     .forEach(System.out::println);
```

* `String::toUpperCase` 直接引用实例方法，代码简洁直观。

---

## **6️⃣ 性能与底层原理**

* 方法引用本质上仍是 Lambda 表达式，JVM 会优化为 **invokedynamic + LambdaMetafactory**
* 性能与对应 Lambda 表达式几乎没有差异
* 优势主要在于可读性和可维护性
* 与下一篇博客的构造器引用相似，都是 Lambda 的简化语法

> ⚡ 这意味着：不要担心方法引用会比 Lambda 慢，它只是语法糖。

---

## **7️⃣ 总结与实践建议**

* 方法引用是 Lambda 的简化语法，可提高代码简洁性与可读性
* 掌握三种类型：对象实例方法、类静态方法、类实例方法
* 实践建议：

    * 尝试将项目中简单 Lambda 替换为方法引用
    * 注意类实例方法引用的参数流向
    * 结合 Stream API 使用，提升代码可读性
