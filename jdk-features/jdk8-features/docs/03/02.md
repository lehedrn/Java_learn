# **构造器引用（Constructor Reference）详解**

**方法引用（Method Reference）**明确了一个结论：

> 方法引用，本质上是 Lambda 的语法糖。

那么问题来了：
**Lambda 只能“调用方法”吗？能不能用来“创建对象”？**

答案是：**可以，而且 Java 8 为此提供了更优雅的语法——构造器引用（Constructor Reference）**。

---

## **1️⃣ 为什么需要构造器引用**

先看一个很常见的 Lambda 写法：

```java
Supplier<List<String>> supplier = () -> new ArrayList<>();
```

这段 Lambda 的逻辑非常简单：

> 调用构造器，创建一个对象。

Java 8 认为：

> 如果 Lambda 的唯一作用就是 `new 一个对象`，那也应该可以像方法引用一样被“引用”。

于是，就有了 **构造器引用**：

```java
Supplier<List<String>> supplier = ArrayList::new;
```

✔ 更简洁
✔ 更语义化
✔ 与方法引用风格保持一致

---

## **2️⃣ 构造器引用的基本概念**

### 定义

**构造器引用**是方法引用的一种特殊形式，用于引用类的构造方法。

### 语法

```java
ClassName::new
```

### 本质

* 仍然是一个 **函数式接口的实例**
* 构造器参数 ↔ 函数式接口方法参数
* `new` 表达式 ↔ Lambda 逻辑体

---

## **3️⃣ 构造器引用与函数式接口的关系**

构造器引用是否能使用，**取决于函数式接口的抽象方法签名**。

| 构造器形式 | 对应函数式接口               |
| ----- | --------------------- |
| 无参构造器 | `Supplier<T>`         |
| 单参构造器 | `Function<T, R>`      |
| 双参构造器 | `BiFunction<T, U, R>` |
| 多参构造器 | 自定义函数式接口              |

---

## **4️⃣ 无参构造器引用**

### Lambda 写法

```java
Supplier<List<String>> supplier = () -> new ArrayList<>();
```

### 构造器引用写法

```java
Supplier<List<String>> supplier = ArrayList::new;
```

### 执行流程

```java
List<String> list = supplier.get();
```

* `get()` 无参数
* 调用 `new ArrayList()`
* 返回创建的对象

📌 **规则总结**

> 函数式接口无参数 → 匹配无参构造器

---

## **5️⃣ 有参构造器引用**

### 示例类

```java
class Person {
    private final String name;

    public Person(String name) {
        this.name = name;
    }
}
```

### Lambda 写法

```java
Function<String, Person> func = name -> new Person(name);
```

### 构造器引用写法

```java
Function<String, Person> func = Person::new;
```

### 调用

```java
Person p = func.apply("Tom");
```

📌 **规则总结**

> 构造器参数列表，必须与函数式接口方法参数完全一致

---

## **6️⃣ 多参数构造器引用**

### 示例类

```java
class User {
    private final String name;
    private final int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

### 使用 `BiFunction`

```java
BiFunction<String, Integer, User> bf = User::new;
User user = bf.apply("Alice", 20);
```

### Lambda 对比

```java
BiFunction<String, Integer, User> bf =
        (name, age) -> new User(name, age);
```

📌 **规则总结**

> 构造器参数个数 = 函数式接口参数个数

---

## **7️⃣ 数组构造器引用（特殊但非常重要）**

数组在 Java 中也是对象，因此也支持构造器引用。

### Lambda 写法

```java
Function<Integer, String[]> func = len -> new String[len];
```

### 构造器引用写法

```java
Function<Integer, String[]> func = String[]::new;
```

### 使用

```java
String[] arr = func.apply(5);
```

📌 **数组构造器引用的特点**

* 参数：数组长度
* 返回值：对应类型的数组

---

## **8️⃣ 构造器引用在 Stream 中的实战场景**

这是构造器引用**最常见、最优雅的使用场景之一**。

### 示例

```java
List<String> names = Arrays.asList("Tom", "Jerry", "Spike");
```

### Lambda 写法

```java
List<Person> people = names.stream()
        .map(name -> new Person(name))
        .collect(Collectors.toList());
```

### 构造器引用写法

```java
List<Person> people = names.stream()
        .map(Person::new)
        .collect(Collectors.toList());
```

✔ 代码更短
✔ 语义更清晰
✔ 非常符合函数式编程风格

---

## **9️⃣ 构造器引用的底层原理（承接上一篇）**

和方法引用一样：

* 构造器引用 **不是提前创建对象**
* JVM 仍然通过
  **invokedynamic + LambdaMetafactory**
* 在运行时动态生成调用逻辑

📌 **结论**

> 构造器引用 ≈ Lambda ≈ 方法引用
> 它们只是语法层面的不同表达，性能基本一致

---

## **🔟 常见误区总结**

### ❌ 误区 1：构造器引用会提前 new 对象

→ ❌ 不会，只是创建函数式接口实例

### ❌ 误区 2：构造器引用只能用于无参构造

→ ❌ 任何参数数量都可以（前提是接口匹配）

### ❌ 误区 3：数组不是构造器

→ ❌ 数组本质也是对象，也有构造语义

---

## **11️⃣ 总结：方法引用 & 构造器引用统一认知**

| 对比项  | 方法引用        | 构造器引用      |
| ---- | ----------- | ---------- |
| 本质   | Lambda 语法糖  | Lambda 语法糖 |
| 引用目标 | 方法          | 构造器        |
| 常见场景 | Stream / 回调 | 对象创建       |
| 可读性  | 高           | 非常高        |

> **统一理解一句话：**
> **方法引用是“调用已有逻辑”的 Lambda 简写，构造器引用是“创建对象”的 Lambda 简写。**
