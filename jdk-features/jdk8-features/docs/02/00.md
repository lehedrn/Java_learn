# Java 8 新特性 · 函数式接口专题

## —— 从接口设计到 JVM 实现

---

## 引言

Java 8 被认为是 Java 语言发展史上的一次分水岭。

它不仅仅引入了 Lambda 表达式、Stream API 这些“看得见”的新语法，更重要的是：
**Java 的类型系统，第一次被正式用来承载“行为本身”。**

在 Java 8 之前，行为只能通过：

* 接口 + 实现类
* 接口 + 匿名内部类

来间接表达。
而 Java 8 之后，我们可以直接把一段“行为”作为参数传递、组合、延迟执行。

但很多人只看到了 **Lambda 的简洁写法**，却忽略了一个更底层、也更关键的事实：

> **Lambda 并不是独立存在的，它必须依附在一种特殊的接口之上 —— 函数式接口（Functional Interface）。**

函数式接口，才是 Java 8 函数式编程模型真正的“类型基石”。

它连接了：

* Java 的接口设计
* 编译期的类型推断
* Lambda 与方法引用
* 以及 JVM 层面的 invokedynamic 与 MethodHandle

如果只把函数式接口理解为“只能有一个方法的接口”，那几乎错过了它 80% 的设计价值。

因此，这个系列将不从语法入手，而是试图回答几个更本质的问题：

* 为什么 Java 一定要引入函数式接口？
* Lambda 的“类型”究竟从哪里来？
* java.util.function 为什么是现在这个样子？
* 方法引用真的只是语法糖吗？
* JVM 是如何在运行期“生成”函数式接口实例的？
* 在真实工程中，函数式接口该如何设计，才不会反噬 API？
