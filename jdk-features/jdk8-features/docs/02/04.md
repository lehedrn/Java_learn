# 方法引用 ≠ 语法糖

## —— 它如何绑定到函数式接口

📌 **定位**：语言设计层 + 类型系统 + JVM 实现

---

## 一、引言

* 方法引用看起来像 Lambda 的简写，但并非简单语法糖
* 它同样依赖 **目标类型（Target Type）**
* 理解方法引用有助于：

    * 掌握函数式接口绑定原理
    * 理解 Lambda / 方法引用在 JVM 的实现差异
    * 减少歧义编译错误

---

## 二、方法引用的基本类型

1. **静态方法引用**：`ClassName::staticMethod`
2. **实例方法引用**：

    * 已知对象：`instance::instanceMethod`
    * 未知对象（通过第一个参数绑定）：`ClassName::instanceMethod`
3. **构造方法引用**：`ClassName::new`

**示例**：

```java
Function<String, Integer> f1 = String::length;      // 未知对象
Consumer<String> c1 = System.out::println;          // 已知对象
Supplier<List<String>> s1 = ArrayList::new;        // 构造方法
```

---

## 三、类型系统视角

1. 方法引用必须绑定**函数式接口的 SAM**
2. 编译器根据目标类型推断：

    * 参数类型
    * 返回类型
3. 方法引用本质上和 Lambda 一样：

    * **没有类型，依赖上下文**
    * 绑定目标 SAM 方法的签名

**示例：不同接口产生歧义**

```java
class Demo {
    static void print(String s) { System.out.println(s); }

    public static void main(String[] args) {
        Consumer<String> c = Demo::print;  // ✅ 知道目标类型
        Runnable r = Demo::print;          // ❌ 参数类型不匹配
    }
}
```

---

## 四、JVM 实现视角

1. **LambdaMetafactory**

    * 方法引用在编译期生成 `invokedynamic` 指令
    * JVM 动态生成匿名类或 Lambda 表达式
2. **区别于 Lambda**

    * Lambda 可以捕获变量
    * 方法引用更直接绑定已有方法或构造函数
3. **性能特点**

    * 方法引用一般比等价 Lambda 更轻量
    * JVM 可重用同一方法句柄

---

## 五、目标类型绑定细节

1. **静态方法** → 参数类型直接映射 SAM
2. **实例方法**：

    * 已知对象 → 绑定对象，SAM 方法参数直接对应剩余参数
    * 未知对象 → 第一个参数作为调用对象
3. **构造方法** → SAM 方法返回值类型必须和构造对象类型一致

---

## 六、实战示例

1. **静态方法引用**

```java
Function<String, Integer> f = Integer::parseInt;
System.out.println(f.apply("123")); // 123
```

2. **实例方法引用（已知对象）**

```java
String prefix = "Hello: ";
Consumer<String> printer = prefix::concat; // 绑定对象
```

3. **实例方法引用（未知对象）**

```java
Function<String, Integer> lengthFunc = String::length; // 第一个参数作为对象
System.out.println(lengthFunc.apply("abc")); // 3
```

4. **构造方法引用**

```java
Supplier<List<String>> listFactory = ArrayList::new;
List<String> list = listFactory.get();
```

5. **编译歧义示例**

```java
class Demo {
    void foo(String s) {}
    void foo(Integer i) {}

    public static void main(String[] args) {
        // Consumer<String> c = Demo::foo; // ❌ 编译错误，重载歧义
    }
}
```

---

## 七、设计哲学与总结

* 方法引用和 Lambda 一样依赖函数式接口
* 并非语法糖，而是**延迟绑定的行为对象**
* JVM 通过 `invokedynamic` 动态生成实例
* 区分已知对象与未知对象、静态方法与构造方法，有助于理解类型系统与性能优化

> 方法引用提供了简洁语法，但背后是类型安全 + JVM 动态生成 + 高性能的实现机制。
