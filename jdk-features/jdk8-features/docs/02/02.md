
# 函数式接口的类型系统视角

## —— Lambda 是如何在 Java 中获得“类型”的？

Java 8 引入 Lambda 表达式时，面临一个根本性问题：

> **Java 是以类为中心的语言，但 Lambda 是一个“无名行为”——它没有类名，没有显式类型，如何被类型系统接纳？**

本文将从语言设计角度解析 Lambda 的类型模型，解释函数式接口如何成为 Lambda 的类型锚点，并通过**可运行的小测试项目示例**展示各种编译约束。

---

## 一、Lambda 的问题定义：它到底有类型吗？

直觉上，很多人会认为 Lambda “无类型”：

```java
() -> System.out.println("hi");   // ❌ 编译错误
Object o = () -> {};              // ❌ 编译错误
```

**原因**：Lambda 本身不是对象，也不是方法，它必须依附于**目标类型（Target Type）**。

> **结论**：Lambda 的类型来自使用位置，而不是自描述。

---

## 二、目标类型（Target Typing）：类型来自上下文

Java 采用 **Target Typing 模型**：

* Lambda 的类型由上下文提供
* 上下文包括：

    * 变量赋值
    * 方法参数
    * 返回值
    * 显式类型转换（cast）

示例：

```java
Runnable r = () -> System.out.println("hello"); // ✅
call(() -> System.out.println("world"));        // ✅
return () -> System.out.println("done");        // ✅
```

> 每个 Lambda 都有唯一的类型锚点——SAM 方法所在的接口。

---

## 三、函数式接口作为类型锚点

Lambda 与 SAM 方法的一一映射，使得函数式接口成为**类型系统唯一合法载体**。

```java
public interface Action {
    void run();
}

Action a = () -> System.out.println("run"); // Lambda 被映射到 run()
```

如果接口不是 SAM：

```java
interface Bad {
    void a();
    void b();
}

Bad b = () -> {}; // ❌ 编译错误
```

> SAM 方法签名是 Lambda 类型推断的唯一依据。

---

## 四、参数类型推断与返回值匹配

### 4.1 参数类型推断

```java
Function<String, Integer> f1 = s -> s.length();
Function<String, Integer> f2 = (String s) -> s.length();
```

* 上下文提供参数类型，编译器自动推断
* 显式类型可提高可读性或解决歧义

### 4.2 返回值匹配

```java
Runnable r = () -> 1;            // ❌ void 与 int 不匹配
Callable<Integer> c = () -> {};  // ❌ SAM 方法返回 Integer，但 Lambda 无返回值
```

控制流不完整也会导致编译失败：

```java
Function<Integer, Integer> f = x -> {
    if (x > 0) return x;
}; // ❌ 并非所有路径都有返回值
```

> 编译器严格保证 Lambda 与 SAM 方法签名一致。

---

## 五、上下文敏感性与合法性差异

同一个 Lambda 在不同上下文下可能合法或非法：

```java
Callable<Integer> c = () -> 1;  // ✅
Runnable r = () -> 1;           // ❌
```

* 原因：Target Type 提供的 SAM 方法不同
* Lambda 的类型是上下文依赖的

---

## 六、重载方法与类型歧义

```java
void test(Runnable r) {}
void test(Callable<Integer> c) {}

test(() -> 1); // ❌ 编译错误：Lambda 可匹配多个目标类型
```

解决方案：显式类型转换

```java
test((Callable<Integer>) () -> 1); // ✅
```

---

## 七、Lambda 与 Object 的非对象性

```java
Runnable r = () -> {};
if (r instanceof Runnable) { // ✅ 可以
    System.out.println("r is Runnable");
}

// ❌ Lambda 不是表达式级对象
// if (() -> {} instanceof Runnable) {}
```

* Lambda 没有类名
* JVM 在运行时通过 invokedynamic 生成匿名实现类实例
* 设计目标：类型安全 + 延迟绑定

## 八、精选小测试项目示例

将前述编译约束整理成可运行的小测试类，读者可在 IDE 中验证。

### 8.1 没有目标类型

```java
// LambdaNoTargetType.java
() -> System.out.println("hi");   // ❌
Object o = () -> {};              // ❌
```

### 8.2 非 SAM 接口

```java
interface Bad { void a(); void b(); }
Bad b = () -> {}; // ❌
```

### 8.3 返回值与 SAM 不匹配

```java
Runnable r = () -> 1;            
Callable<Integer> c = () -> {};  
```

### 8.4 控制流不完整

```java
Function<Integer, Integer> f = x -> { if (x > 0) return x; };
```

### 8.5 上下文敏感

```java
Callable<Integer> c = () -> 1;  // ✅
Runnable r = () -> 1;           // ❌
```

### 8.6 重载歧义

```java
void test(Runnable r) {}
void test(Callable<Integer> c) {}
test(() -> 1);                       // ❌
test((Callable<Integer>) () -> 1);   // ✅
```

### 8.7 Lambda 不能直接 instanceof

```java
Runnable r = () -> {};
if (r instanceof Runnable) {}           // ✅
// if (() -> {} instanceof Runnable) {}  // ❌
```

## 九、小结：Lambda 的类型模型

1. Lambda 类型由**上下文中的函数式接口**提供
2. SAM 方法签名是推断依据
3. 参数类型、返回值类型、控制流必须一致
4. Lambda 合法性是上下文敏感的
5. 重载可能产生歧义，需要显式类型转换
6. Lambda 不是普通对象，JVM 运行期生成匿名实现类

> Lambda 的类型系统，是**延迟绑定行为模型**，函数式接口是其核心锚点。
