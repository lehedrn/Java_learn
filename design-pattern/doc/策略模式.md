# 策略模式

## 一、概述

**策略模式（Strategy Pattern）** 是一种行为型设计模式，它定义了一系列可互换的算法，并使每个算法都可以独立变化。客户端可以在运行时选择使用哪种算法。

### 1.1 核心思想

- **封装算法**：将每个算法封装在独立的策略类中
- **自由切换**：可以在运行时动态切换策略
- **组合优于继承**：使用组合代替继承来实现算法复用

### 1.2 解决的问题

1. **多重条件判断**
   - 避免大量的 if-else 或 switch 语句
   - 使代码更易读、易维护

2. **算法复用**
   - 每个策略类独立实现一个算法
   - 可以在不同场景中复用

3. **开闭原则**
   - 新增策略无需修改现有代码
   - 只需添加新的策略类

### 1.3 生活中的例子

| 场景 | 策略 | 说明 |
|------|------|------|
| **支付方式** | 支付宝/微信/银行卡 | 同一订单，不同支付方式 |
| **会员折扣** | 普通/VIP/超级 VIP | 不同等级享受不同折扣 |
| **快递选择** | 顺丰/中通/邮政/京东 | 同一包裹，不同快递 |
| **导航路线** | 最快/最短/最省钱 | 同一路线，不同偏好 |

## 二、基础用法：电商购物车支付

### 2.1 场景介绍

**电商购物车**：用户下单时可以选择不同的支付方式（支付宝、微信、银行卡），每种支付方式的实现不同，但都完成"支付"这个动作。

### 2.2 核心代码

**策略接口 - PaymentStrategy**

```java
/**
 * 支付策略接口
 * 定义所有支付方式的公共方法
 */
public interface PaymentStrategy {
    /**
     * 执行支付
     * @param amount 支付金额
     * @return 是否成功
     */
    boolean pay(double amount);

    /**
     * 获取支付方式名称
     */
    String getPaymentMethod();
}
```


## 三、进阶用法 1：策略 + 工厂 - 会员折扣系统

### 3.1 场景介绍

**电商会员系统**：根据会员等级（普通/VIP/超级 VIP）自动应用对应的折扣策略，使用工厂模式统一管理策略创建。

### 3.2 核心代码

**折扣策略接口**

```java
public interface DiscountStrategy {
    /**
     * 计算折扣后的价格
     * @param originalPrice 原价
     * @return 折后价
     */
    double calculateDiscount(double originalPrice);

    /**
     * 获取折扣名称
     */
    String getDiscountName();
}
```

**具体策略实现**

```java

    }

// VIP 会员 9 折
```

**策略工厂 - DiscountStrategyFactory**

```java
public class DiscountStrategyFactory {

    public enum MemberLevel {
        NORMAL,      // 普通会员
        VIP,         // VIP 会员
        SUPER_VIP,   // 超级 VIP
        NONE         // 非会员
    }

    // 使用 EnumMap 缓存策略，避免重复创建
    private static final Map<MemberLevel, DiscountStrategy> strategyCache;

    static {
        strategyCache = new EnumMap<>(MemberLevel.class);
        strategyCache.put(MemberLevel.NORMAL, new NormalMemberDiscount());
        strategyCache.put(MemberLevel.VIP, new VipMemberDiscount());
        strategyCache.put(MemberLevel.SUPER_VIP, new SuperVipMemberDiscount());
        strategyCache.put(MemberLevel.NONE, new NoDiscount());
    }

    /**
     * 根据会员等级获取折扣策略
     */
    public static DiscountStrategy getStrategy(MemberLevel level) {
        return strategyCache.get(level);
    }
}
```

**订单服务 - OrderService**

```java
public class OrderService {
    private DiscountStrategy discountStrategy;

    /**
     * 设置会员等级（通过工厂获取策略）
     */
    public void setMemberLevel(DiscountStrategyFactory.MemberLevel level) {
        this.discountStrategy = DiscountStrategyFactory.getStrategy(level);
        System.out.println("✅ 已应用折扣：" + discountStrategy.getDiscountName());
    }

    /**
     * 计算订单最终价格
     */
    public double calculateFinalPrice(double originalPrice) {
        if (discountStrategy == null) {
            System.out.println("❌ 请先设置会员等级");
            return originalPrice;
        }
        return discountStrategy.calculateDiscount(originalPrice);
    }
}
```

### 3.4 策略 + 工厂的优点

| 优点 | 说明 |
|------|------|
| **统一创建** | 客户端无需知道策略的具体实现 |
| **缓存复用** | 使用 EnumMap 缓存，避免重复创建 |
| **易于扩展** | 新增策略只需修改工厂 |
| **类型安全** | 使用枚举保证类型安全 |

## 四、进阶用法 2：策略 + 枚举 - 快递运费计算

### 4.1 场景介绍

**快递运费计算**：不同快递公司有不同的计费规则，使用枚举实现策略模式，代码更简洁。

### 4.2 核心代码

**运费策略接口**

```java
public interface ShippingStrategy {
    /**
     * 计算运费
     * @param weight 重量（kg）
     * @param distance 距离（km）
     * @return 运费
     */
    double calculateShippingFee(double weight, double distance);

    /**
     * 获取快递公司名称
     */
    String getCourierName();

    /**
     * 预估送达天数
     */
    int estimateDeliveryDays(double distance);
}
```

**枚举实现策略 - CourierStrategy**

```java
public enum CourierStrategy implements ShippingStrategy {
    SF_EXPRESS("顺丰速运") {
        @Override
        public double calculateShippingFee(double weight, double distance) {
            double base = 15; // 首重 1kg 内 15 元
            double extra = Math.ceil(weight - 1) * 10; // 续重每 kg10 元
            double distanceFee = distance > 1000 ? 5 : 0; // 超 1000km 加 5 元
            return base + extra + distanceFee;
        }

        @Override
        public int estimateDeliveryDays(double distance) {
            return distance > 1000 ? 2 : 1;
        }
    },

    ZTO_EXPRESS("中通快递") {
        @Override
        public double calculateShippingFee(double weight, double distance) {
            double base = 10; // 首重 1kg 内 10 元
            double extra = Math.ceil(weight - 1) * 6; // 续重每 kg6 元
            return base + extra;
        }

        @Override
        public int estimateDeliveryDays(double distance) {
            return distance > 500 ? 3 : 2;
        }
    },

    CHINA_POST("邮政平邮") {
        @Override
        public double calculateShippingFee(double weight, double distance) {
            return 5 + weight * 1; // 5 元基础 + 每公斤 1 元
        }

        @Override
        public int estimateDeliveryDays(double distance) {
            return 5 + (int)(distance / 500);
        }
    },

    JD_LOGISTICS("京东物流") {
        @Override
        public double calculateShippingFee(double weight, double distance) {
            return 6 + weight * 2; // 6 元基础 + 每公斤 2 元
        }

        @Override
        public int estimateDeliveryDays(double distance) {
            return distance > 300 ? 2 : 1;
        }
    };

    private final String courierName;

    CourierStrategy(String courierName) {
        this.courierName = courierName;
    }

    @Override
    public String getCourierName() {
        return courierName;
    }
}
```

**运费计算器 - ShippingCalculator**

```java
public class ShippingCalculator {
    private ShippingStrategy strategy;

    /**
     * 设置快递公司
     */

     * 计算运费

}
```

**导航系统 - NavigationSystem**

```java
public class NavigationSystem {
    private RouteStrategy currentStrategy;
    private String currentStart;
    private String currentEnd;

    /**
     * 设置路线策略（支持运行时动态切换）
     */
    public void setRouteStrategy(RouteStrategy strategy) {
        this.currentStrategy = strategy;
        System.out.println("✅ 已切换策略：" + strategy.getStrategyName() + "\n");
    }

    /**
     * 设置目的地
     */
    public void setDestination(String start, String end) {
        this.currentStart = start;
        this.currentEnd = end;
        System.out.println("📍 路线：" + start + " → " + end);
    }

    /**
     * 开始导航
     */
    public RouteResult startNavigation() {
        if (currentStrategy == null) {
            System.out.println("❌ 请先选择路线偏好");
            return null;
        }
        System.out.println("🧭 开始规划路线...\n");
        return currentStrategy.planRoute(currentStart, currentEnd);
    }

    /**
     * 比较所有策略的路线结果
     */
    public void compareAllStrategies() {
        System.out.println("\n📊 对比所有路线方案：");
        System.out.println("路线：" + currentStart + " → " + currentEnd);

        RouteStrategy[] strategies = {
            new FastestRouteStrategy(),
            new ShortestDistanceStrategy(),
            new LeastCostStrategy()
        };

        for (RouteStrategy strategy : strategies) {
            System.out.println("--- 方案：" + strategy.getStrategyName() + " ---");
            RouteResult result = strategy.planRoute(currentStart, currentEnd);
            System.out.println("结果：" + result + "\n");
        }
    }
}
```

```
结果：少收费路线 | 距离：30.0km | 时间：50 分钟 | 费用：￥2.0
```

### 5.4 动态切换的优势

| 优势 | 说明 |
|------|------|
| **运行时切换** | 无需重新创建上下文对象 |
| **用户自主选择** | 用户可以根据需求随时切换 |
| **对比决策** | 可以比较不同策略的结果 |
| **灵活应变** | 适应变化的业务场景 |

## 六、四种实现方式对比

| 实现方式 | 特点 | 适用场景 | 优点 |
|---------|------|---------|------|
| **基础用法** | 直接设置策略对象 | 简单场景，策略数量少 | 简单直接，易理解 |
| **策略 + 工厂** | 通过工厂获取策略 | 策略有明确的分类/等级 | 统一创建，缓存复用 |
| **策略 + 枚举** | 枚举实现策略接口 | 策略固定且数量有限 | 代码简洁，单例保证 |
| **动态切换** | 运行时切换策略 | 需要支持用户实时选择 | 灵活应变，支持对比 |

## 七、优缺点分析

### 7.1 优点

1. **消除条件判断**
   - 避免大量的 if-else 或 switch 语句
   - 代码更清晰、易读

2. **符合开闭原则**
   - 新增策略无需修改现有代码
   - 只需添加新的策略类

3. **算法独立**
   - 每个策略类独立实现一个算法
   - 便于理解和维护

4. **可以动态切换**
   - 支持运行时切换策略
   - 灵活适应不同场景

### 7.2 缺点

1. **类数量增加**
   - 每个策略需要一个独立的类
   - 可能导致类的数量增多

2. **客户端需要知道所有策略**
   - 客户端需要选择合适的策略
   - 增加了客户端的理解成本

3. **策略可能重复**
   - 如果策略数量不多
   - 可能显得过度设计

## 八、适用场景

### 8.1 适合使用策略模式的场景

1. **多个类只有算法不同**
   - 多个类实现相似功能
   - 只是算法实现不同

2. **不想使用条件判断**
   - 代码中有大量 if-else
   - 难以维护

3. **需要动态切换算法**
   - 运行时需要根据情况切换算法
   - 用户可以选择不同的算法

4. **算法需要独立复用**
   - 每个算法可能在不同地方使用
   - 算法需要独立测试

### 8.2 实际应用示例

1. **Java Comparator**
   ```java
   // 不同的比较策略
   list.sort(Comparator.naturalOrder());
   list.sort(Comparator.reverseOrder());
   list.sort((a, b) -> b.length() - a.length());
   ```

2. **Spring HandlerInterceptor**
   ```java
   // 不同的拦截器策略
   registry.addInterceptor(new AuthInterceptor());
   registry.addInterceptor(new LogInterceptor());
   ```

3. **Java Stream API**
   ```java
   // 不同的收集策略
   list.stream().collect(Collectors.toList());
   list.stream().collect(Collectors.toSet());
   list.stream().collect(Collectors.toMap(...));
   ```

## 九、与其他模式的关系

### 9.1 策略模式 vs 状态模式

| 对比项 | 策略模式 | 状态模式 |
|--------|---------|---------|
| **目的** | 选择不同的算法 | 表示不同的状态 |
| **切换** | 客户端主动切换 | 对象内部状态变化 |
| **关注点** | 怎么做（How） | 是什么（What） |

### 9.2 策略模式 vs 模板方法模式

| 对比项 | 策略模式 | 模板方法模式 |
|--------|---------|-------------|
| **实现方式** | 组合 | 继承 |
| **灵活性** | 高（运行时切换） | 低（编译时确定） |
| **复用粒度** | 完整算法 | 算法骨架 |

### 9.3 策略模式 vs 工厂模式

- **工厂模式**：解决对象创建问题
- **策略模式**：解决算法选择问题
- **结合使用**：工厂模式可以创建策略对象

## 十、最佳实践

### 10.1 设计建议

1. **策略类保持无状态**
   - 便于缓存和复用
   - 避免线程安全问题

2. **使用工厂统一管理**
   - 隐藏策略创建细节
   - 方便缓存策略实例

3. **策略接口设计合理**
   - 方法不宜过多
   - 保证各策略实现的一致性

4. **文档化各策略的差异**
   - 说明每个策略的特点
   - 帮助客户端选择合适的策略

### 10.2 避免过度使用

1. **策略很少变化**
   - 如果算法基本不变
   - 可能不需要策略模式

2. **策略之间有状态共享**
   - 策略之间需要共享状态
   - 可能导致设计复杂

3. **性能敏感场景**
   - 频繁创建策略对象
   - 需要考虑缓存或单例

## 十一、总结

策略模式是一种**行为型模式**，它通过**封装算法**并将每个算法独立实现，使得算法可以在运行时自由切换。

**关键要点：**
- 策略接口：定义算法的公共方法
- 具体策略：实现不同的算法
- 上下文：持有策略引用并调用

**四种实现方式：**
1. **基础用法**：直接设置策略对象（支付方式）
2. **策略 + 工厂**：通过工厂获取策略（会员折扣）
3. **策略 + 枚举**：枚举实现策略接口（快递运费）
4. **动态切换**：运行时切换策略（导航路线）

**经典应用：**
- Java Comparator 比较器
- Spring HandlerInterceptor 拦截器
- Java Stream Collector 收集器

策略模式让你能够**封装算法**、**消除条件判断**，并在运行时**灵活切换**不同的实现方式！
