# 组合模式

## 一、概述

**组合模式（Composite Pattern）** 是一种结构型设计模式，它将对象组合成树形结构以表示"部分 - 整体"的层次结构，使得用户对单个对象和组合对象的使用具有一致性。

### 1.1 核心思想

- **树形结构**：用树形结构表示层次关系
- **一致性**：对单个对象和组合对象的操作一致
- **递归组合**：子节点本身也可以是组合
- **透明性**：客户端无需区分叶子节点和组合节点

### 1.2 解决的问题

1. **层次结构复杂**
   - 系统中有树形结构的数据
   - 需要统一处理单个对象和组合对象

2. **代码重复**
   - 遍历树形结构需要大量递归代码
   - 客户端需要区分叶子节点和分支节点

3. **使用不一致**
   - 单个对象和组合对象的操作方式不同
   - 客户端代码复杂，需要类型判断

### 1.3 生活中的例子

| 场景 | 说明 |
|------|------|
| **公司组织架构** | 员工和部门，部门可以包含员工和其他部门 |
| **文件系统** | 文件和文件夹，文件夹可以包含文件和其他文件夹 |
| **菜单系统** | 菜单项和子菜单，子菜单可以包含菜单项 |
| **电商订单** | 商品和礼品盒，礼品盒可以包含商品和其他礼品盒 |
| **图形组合** | 基本图形和组合图形，组合图形可以包含多个图形 |

## 二、模式结构

### 2.1 角色组成

1. **组件（Component）** - [`FileSystemNode`](../src/main/java/com/coderlee/designpattern/structural/composite/FileSystemNode.java)、[`OrderItem`](../src/main/java/com/coderlee/designpattern/structural/composite/OrderItem.java)
   - 定义所有对象的公共接口
   - 声明添加、移除子节点的方法（可选）
   - 声明访问子节点的方法（可选）

2. **叶子节点（Leaf）** - [`File`](../src/main/java/com/coderlee/designpattern/structural/composite/File.java)、[`Product`](../src/main/java/com/coderlee/designpattern/structural/composite/Product.java)
   - 没有子节点的组件
   - 实现组件接口的基本操作
   - 对添加、移除子节点的方法抛出异常

3. **组合节点（Composite）** - [`Folder`](../src/main/java/com/coderlee/designpattern/structural/composite/Folder.java)、[`GiftBox`](../src/main/java/com/coderlee/designpattern/structural/composite/GiftBox.java)、[`Order`](../src/main/java/com/coderlee/designpattern/structural/composite/Order.java)
   - 有子节点的组件
   - 实现添加、移除、访问子节点的方法
   - 递归地将操作委托给子节点

## 三、代码示例（文件系统）

### 3.1 组件接口

```java
// FileSystemNode.java - 文件系统节点接口
public interface FileSystemNode {
    void show(String indent);
    long getSize();
    void search(String name);

    // 默认方法，叶子节点不支持
    default void add(FileSystemNode node) {
        throw new UnsupportedOperationException("叶子节点不支持添加操作");
    }

    default void remove(FileSystemNode node) {
        throw new UnsupportedOperationException("叶子节点不支持移除操作");
    }

    default FileSystemNode getChild(int index) {
        throw new UnsupportedOperationException("叶子节点不支持获取子节点操作");
    }
}
```

### 3.2 叶子节点

```java
// File.java - 文件（叶子节点）
public class File implements FileSystemNode {
    private String name;
    private long size;

    public File(String name, long size) {
        this.name = name;
        this.size = size;
    }

    @Override
    public void show(String indent) {
        System.out.println(indent + "📄 " + name + " (" + size + " B)");
    }

    @Override
    public long getSize() {
        return size;
    }

    @Override
    public void search(String name) {
        if (this.name.equals(name)) {
            System.out.println("找到文件：" + name);
        }
    }
}
```

### 3.3 组合节点

```java
// Folder.java - 文件夹（组合节点）
public class Folder implements FileSystemNode {
    private String name;
    private List<FileSystemNode> children;

    public Folder(String name) {
        this.name = name;
        this.children = new ArrayList<>();
    }

    @Override
    public void show(String indent) {
        System.out.println(indent + "📁 " + name);
        for (FileSystemNode node : children) {
            node.show(indent + "    ");  // 递归显示子节点
        }
    }

    @Override
    public long getSize() {
        long totalSize = 0;
        for (FileSystemNode node : children) {
            totalSize += node.getSize();  // 递归累加大小
        }
        return totalSize;
    }

    @Override
    public void search(String name) {
        if (this.name.equals(name)) {
            System.out.println("找到文件夹：" + name);
        }
        for (FileSystemNode node : children) {
            node.search(name);  // 递归搜索子节点
        }
    }

    @Override
    public void add(FileSystemNode node) {
        children.add(node);
    }

    @Override
    public void remove(FileSystemNode node) {
        children.remove(node);
    }
}
```

### 3.4 客户端使用

```java
// FileSystemDemo.java - 演示类
public class FileSystemDemo {
    public static void main(String[] args) {
        // 创建文件
        File file1 = new File("简历.pdf", 1024 * 100);
        File file2 = new File("照片.jpg", 1024 * 500);

        // 创建文件夹
        Folder root = new Folder("根目录");
        Folder workFolder = new Folder("工作文档");

        // 构建树形结构
        root.add(file1);
        root.add(workFolder);
        workFolder.add(file2);

        // 统一操作：无需区分文件和文件夹
        root.show("");           // 显示目录树
        root.getSize();          // 计算总大小
        root.search("简历.pdf");  // 搜索文件
    }
}
```

**输出结果：**
```
📁 根目录
    📄 简历.pdf (102400 B)
    📁 工作文档
        📄 照片.jpg (512000 B)
```

## 四、代码示例（电商订单）

### 4.1 组件接口

```java
// OrderItem.java - 订单项接口
public interface OrderItem {
    void show(String indent);
    double getPrice();
    int getQuantity();
    default void add(OrderItem item) {
        throw new UnsupportedOperationException("单个商品不支持添加操作");
    }
    default void remove(OrderItem item) {
        throw new UnsupportedOperationException("单个商品不支持移除操作");
    }
}
```

### 4.2 叶子节点

```java
// Product.java - 商品
public class Product implements OrderItem {
    private String name;
    private double price;
    private int quantity;

    @Override
    public void show(String indent) {
        System.out.println(indent + "🛒 " + name + " × " + quantity
                + " = ￥" + String.format("%.2f", getPrice()));
    }

    @Override
    public double getPrice() {
        return price * quantity;
    }

    @Override
    public int getQuantity() {
        return quantity;
    }
}
```

### 4.3 组合节点

```java
// GiftBox.java - 礼品盒
public class GiftBox implements OrderItem {
    private String name;
    private List<OrderItem> items;

    @Override
    public void show(String indent) {
        System.out.println(indent + "🎁 " + name + " [礼品盒]");
        for (OrderItem item : items) {
            item.show(indent + "    ");  // 递归显示
        }
    }

    @Override
    public double getPrice() {
        double total = 0;
        for (OrderItem item : items) {
            total += item.getPrice();  // 递归累加
        }
        return total;
    }

    @Override
    public void add(OrderItem item) {
        items.add(item);
    }
}
```

### 4.4 客户端使用

```java
// OrderDemo.java - 演示类
public class OrderDemo {
    public static void main(String[] args) {
        // 创建商品
        Product phone = new Product("iPhone 15", 5999.00, 1);
        Product earbuds = new Product("AirPods", 1299.00, 1);

        // 创建礼品盒
        GiftBox giftBox = new GiftBox("新年大礼包");
        giftBox.add(earbuds);

        // 创建订单
        Order order = new Order("20240115001");
        order.add(phone);
        order.add(giftBox);

        // 统一操作
        order.show("");
        System.out.println("总价：￥" + order.getPrice());
    }
}
```

**输出结果：**
```
📋 订单号：20240115001
    🛒 iPhone 15 × 1 = ￥5999.00
    🎁 新年大礼包 [礼品盒]
        🛒 AirPods × 1 = ￥1299.00
总价：￥7298.00
```

## 五、组合模式的两种形式

### 5.1 透明组合模式（推荐）

在组件接口中声明所有方法（包括添加、移除子节点）：

```java
public interface Component {
    void add(Component c);
    void remove(Component c);
    void operation();
}

// 叶子节点实现时抛出异常
public class Leaf implements Component {
    public void add(Component c) {
        throw new UnsupportedOperationException();
    }
    // ...
}
```

| 优点 | 缺点 |
|------|------|
| 客户端无需区分叶子和组合 | 叶子节点调用 add 会报错 |
| 接口统一，透明性好 | 违反单一职责原则 |

### 5.2 安全组合模式

只在组合节点中声明添加、移除子节点的方法：

```java
public interface Component {
    void operation();
}

public interface Composite extends Component {
    void add(Component c);
    void remove(Component c);
}
```

| 优点 | 缺点 |
|------|------|
| 叶子节点不会有非法方法 | 客户端需要区分类型 |
| 符合单一职责原则 | 透明性差 |

### 5.3 本示例的实现方式

本示例采用**透明组合模式 + 默认方法**的方式：

```java
public interface FileSystemNode {
    default void add(FileSystemNode node) {
        throw new UnsupportedOperationException("叶子节点不支持添加操作");
    }
}
```

这样既保持了透明性，又避免了在叶子节点中重复编写异常代码。

## 六、优缺点分析

### 6.1 优点

1. **简化客户端代码**
   - 客户端无需区分叶子节点和组合节点
   - 使用统一接口操作所有对象

2. **易于添加新元素**
   - 新增叶子节点或组合节点无需修改现有代码
   - 符合开闭原则

3. **方便递归遍历**
   - 树形结构天然支持递归
   - 代码简洁优雅

4. **层次结构清晰**
   - 直观地表示部分 - 整体关系
   - 易于理解和维护

### 6.2 缺点

1. **违反接口隔离原则**
   - 叶子节点被迫实现不需要的方法
   - 通过抛出异常或返回空来处理

2. **增加设计复杂度**
   - 需要仔细设计组件接口
   - 要权衡透明性和安全性

3. **可能的性能问题**
   - 深度递归可能导致栈溢出
   - 大量遍历操作影响性能

## 七、适用场景

### 7.1 适合使用组合模式的场景

1. **树形结构数据**
   - 文件系统、组织架构、菜单系统
   - DOM 树、XML/JSON 解析

2. **部分 - 整体层次**
   - 订单和商品、图形组合
   - 军队编制（军 - 师 - 团 - 营）

3. **统一操作需求**
   - 需要对单个对象和组合对象做相同操作
   - 操作可以递归执行

### 7.2 实际应用示例

1. **Java Swing/AWT 组件树**
   ```java
   Container panel = new JPanel();
   panel.add(new JButton("按钮"));
   panel.add(new JTextField("输入框"));
   // Container 可以包含其他 Container
   ```

2. **XML/HTML DOM 树**
   ```java
   Node root = document.getDocumentElement();
   NodeList children = root.getChildNodes();
   // 递归遍历所有节点
   ```

3. **企业组织架构**
   - 部门可以包含员工和子部门
   - 计算总人数、总工资

4. **菜单系统**
   - 菜单可以包含菜单项和子菜单
   - 渲染菜单、执行命令

## 八、与其他模式的关系

### 8.1 组合模式 vs 装饰器模式

| 对比项 | 组合模式 | 装饰器模式 |
|--------|---------|-----------|
| **目的** | 表示树形结构 | 动态增强功能 |
| **结构** | 一对多（父子关系） | 一对一（包装关系） |
| **节点类型** | 叶子和组合 | 组件和装饰器 |

### 8.2 组合模式 vs 迭代器模式

- 组合模式经常与迭代器模式结合使用
- 用迭代器遍历组合对象的子节点

### 8.3 组合模式 vs 责任链模式

| 对比项 | 组合模式 | 责任链模式 |
|--------|---------|-----------|
| **目的** | 表示层次结构 | 依次处理请求 |
| **结构** | 树形 | 链式 |

## 九、最佳实践

### 9.1 设计建议

1. **明确组件接口**
   - 只声明真正需要的方法
   - 避免接口过于臃肿

2. **选择合适的组合形式**
   - 需要透明性：选透明组合模式
   - 需要安全性：选安全组合模式

3. **提供便捷方法**
   - 在组合节点中提供批量操作方法
   - 简化客户端调用

4. **注意循环引用**
   - 防止子节点指向父节点造成循环
   - 在 add/remove 时做检查

### 9.2 扩展示例

**文件系统新增功能：**

```java
// 在 FileSystemNode 中添加
default void delete() {
    System.out.println("删除 " + this);
}

// 在 Folder 中实现
public void delete() {
    for (FileSystemNode node : children) {
        node.delete();  // 递归删除
    }
    System.out.println("删除文件夹 " + name);
}
```

**订单系统新增折扣：**

```java
// 在 Order 中添加
private double discount = 1.0;

public void setDiscount(double discount) {
    this.discount = discount;
}

@Override
public double getPrice() {
    double total = 0;
    for (OrderItem item : items) {
        total += item.getPrice();
    }
    return total * discount;  // 应用折扣
}
```

## 十、总结

组合模式是一种用于处理树形结构的强大模式，它通过**统一单个对象和组合对象的操作**，简化了客户端代码。

**关键要点：**
- 组件：定义统一的接口
- 叶子节点：没有子节点的基本对象
- 组合节点：包含子节点，递归执行操作
- 树形结构：表示部分 - 整体关系

**设计原则：**
- 开闭原则：新增节点类型无需修改现有代码
- 单一职责原则：叶子节点和组合节点各司其职
- 组合复用原则：优先使用组合而非继承

**经典应用：**
- 文件系统的目录结构
- UI 组件树（Swing、React）
- XML/HTML DOM 解析
- 电商订单系统

组合模式让你能够以**一致的方式**处理简单元素和复杂组合，是处理层次结构数据的理想选择！
