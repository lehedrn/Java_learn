# 适配器模式

## 一、概述

**适配器模式（Adapter Pattern）** 是一种结构型设计模式，它允许接口不兼容的类一起工作。就像现实生活中的电源适配器，让不同规格的设备能够连接使用。

### 1.1 核心思想

- **接口转换**：将一个类的接口转换成客户期望的另一个接口
- **消除不兼容**：使原本无法一起工作的类可以协同工作
- **复用现有代码**：无需修改现有类即可复用其功能
- **透明包装**：客户端通过目标接口与适配器交互，无需关心适配细节

### 1.2 解决的问题

1. **接口不匹配**
   - 现有类的接口与客户端期望的接口不一致
   - 需要复用现有类但无法修改其接口

2. **系统迁移兼容**
   - 新旧系统接口不同，需要平滑过渡
   - 第三方库接口与系统标准不一致

3. **代码复用需求**
   - 想让现有类在新环境中复用
   - 避免重写已有功能的代码

### 1.3 生活中的例子

| 场景 | 说明 |
|------|------|
| **电源适配器** | 将 220V 交流电转换为 5V 直流电，给手机充电 |
| **USB 转接头** | 将 USB-A 接口转换为 USB-C 接口 |
| **翻译官** | 将一种语言翻译为另一种语言，促进交流 |
| **读卡器** | 将 SD 卡接口转换为 USB 接口，让电脑读取 |

## 二、模式结构

### 2.1 角色组成

1. **目标接口（Target）** - [`Power5V`](../src/main/java/com/coderlee/designpattern/structural/adapter/Power5V.java)
   - 客户端期望的接口
   - 定义了客户端使用的标准

2. **被适配者（Adaptee）** - [`Power220V`](../src/main/java/com/coderlee/designpattern/structural/adapter/Power220V.java)
   - 需要适配的现有类
   - 其接口与目标接口不兼容

3. **适配器（Adapter）** - [`PowerAdapter`](../src/main/java/com/coderlee/designpattern/structural/adapter/PowerAdapter.java)
   - 实现目标接口，包装被适配者
   - 将目标接口的调用转换为被适配者的调用

## 三、代码示例

### 3.1 目标接口

```java
// Power5V.java - 目标接口
public interface Power5V {
    /**
     * 输出 5V 电压
     * @return 电压值
     */
    int output5V();
}
```

### 3.2 被适配者

```java
// Power220V.java - 被适配者（220V 交流电）
public class Power220V {
    public int output220V() {
        System.out.println("Power220V: 输出 220V 交流电");
        return 220;
    }
}
```

### 3.3 对象适配器（推荐）

```java
// PowerAdapter.java - 对象适配器
public class PowerAdapter implements Power5V {
    private Power220V power220V;

    public PowerAdapter(Power220V power220V) {
        this.power220V = power220V;
    }

    @Override
    public int output5V() {
        System.out.println("PowerAdapter: 开始转换电压...");
        int sourceVoltage = power220V.output220V();
        System.out.println("PowerAdapter: 将 " + sourceVoltage + "V 转换为 5V");
        return 5;
    }
}
```

### 3.4 类适配器

```java
// PowerAdapterClass.java - 类适配器
public class PowerAdapterClass extends Power220V implements Power5V {
    @Override
    public int output5V() {
        System.out.println("PowerAdapterClass: 开始转换电压...");
        int sourceVoltage = output220V();  // 调用父类方法
        System.out.println("PowerAdapterClass: 将 " + sourceVoltage + "V 转换为 5V");
        return 5;
    }
}
```

### 3.5 客户端使用

```java
// MobilePhone.java - 客户端（手机）
public class MobilePhone {
    public void charge(Power5V power5V) {
        int voltage = power5V.output5V();
        if (voltage == 5) {
            System.out.println("MobilePhone: 电压正常，开始充电 🔋");
        } else {
            System.out.println("MobilePhone: 电压异常，无法充电 ⚠️");
        }
    }
}

// AdapterDemo.java - 演示
public class AdapterDemo {
    public static void main(String[] args) {
        MobilePhone phone = new MobilePhone();
        Power220V power220V = new Power220V();

        // 使用对象适配器
        Power5V adapter = new PowerAdapter(power220V);
        phone.charge(adapter);
    }
}
```

**输出结果：**
```
PowerAdapter: 开始转换电压...
Power220V: 输出 220V 交流电
PowerAdapter: 将 220V 转换为 5V
MobilePhone: 电压正常，开始充电 🔋
```

## 四、适配器模式的三种变体

### 4.1 类适配器模式

使用**继承**实现适配器：

```java
public class PowerAdapterClass extends Power220V implements Power5V {
    @Override
    public int output5V() {
        int sourceVoltage = output220V();  // 继承父类方法
        return 5;
    }
}
```

| 优点 | 缺点 |
|------|------|
| 可以直接调用被适配者的 protected 方法 | Java 只能单继承，一次只能适配一个类 |
| 不需要额外持有被适配者引用 | 耦合度高，不灵活 |
| 代码相对简洁 | 不符合组合复用原则 |

### 4.2 对象适配器模式 ⭐推荐

使用**组合**实现适配器：

```java
public class PowerAdapter implements Power5V {
    private Power220V power220V;  // 组合

    public PowerAdapter(Power220V power220V) {
        this.power220V = power220V;
    }

    @Override
    public int output5V() {
        return 5;
    }
}
```

| 优点 | 缺点 |
|------|------|
| 耦合度低，更灵活 | 需要额外持有被适配者引用 |
| 可以适配多个类（组合多个对象） | 代码稍多 |
| 符合组合复用原则 | |
| 符合开闭原则 | |

### 4.3 缺省适配器模式

当接口有多个方法，但客户端只需要其中部分方法时使用：

```java
// OldLogger.java - 旧接口有 4 个方法
public interface OldLogger {
    void debug(String msg);
    void info(String msg);
    void warn(String msg);
    void error(String msg);
}

// AbstractLoggerAdapter.java - 抽象适配器提供空实现
public abstract class AbstractLoggerAdapter implements OldLogger {
    @Override public void debug(String msg) {}
    @Override public void info(String msg) {}
    @Override public void warn(String msg) {}
    @Override public void error(String msg) {}
}

// ErrorLoggerAdapter.java - 具体适配器只需重写需要的方法
public class ErrorLoggerAdapter extends AbstractLoggerAdapter implements TargetLogger {
    @Override
    public void error(String msg) {
        System.out.println("[ERROR] " + msg);
    }

    @Override
    public void log(String msg) {
        error(msg);  // 委托给 error 方法
    }
}
```

## 五、优缺点分析

### 5.1 优点

1. **让不兼容的类协同工作**
   - 解决了接口不匹配的问题
   - 使复用现有代码成为可能

2. **符合开闭原则**
   - 增加新的适配器无需修改现有代码
   - 易于扩展和维护

3. **提高代码复用性**
   - 可以复用现有的类
   - 避免重复造轮子

4. **透明性好**
   - 客户端通过目标接口访问
   - 无需关心适配细节

5. **灵活性强**
   - 对象适配器可以适配多个类
   - 可以在运行时选择使用哪个适配器

### 5.2 缺点

1. **增加代码复杂度**
   - 引入额外的类（适配器类）
   - 需要理解多个角色之间的关系

2. **过度使用会混乱**
   - 过多适配器会让系统难以理解
   - 应该优先考虑重新设计接口

3. **性能开销**
   - 多了一层调用
   - 对性能敏感的场景需考虑

## 六、适用场景

### 6.1 适合使用适配器模式的场景

1. **接口不匹配**
   - 现有类接口与期望接口不同
   - 需要复用但无法修改

2. **系统迁移**
   - 新旧系统接口不同
   - 需要平滑过渡

3. **第三方库集成**
   - 第三方库接口与系统标准不一致
   - 需要统一接口标准

4. **日志系统适配**
   - 需要适配不同的日志框架
   - 统一日志接口

### 6.2 实际应用示例

1. **Java I/O 流**
   ```java
   // InputStreamReader 是字节流和字符流的适配器
   InputStream fis = new FileInputStream("file.txt");
   Reader isr = new InputStreamReader(fis);  // 适配器
   BufferedReader br = new BufferedReader(isr);
   ```

2. **Spring MVC 的适配器**
   - `HandlerAdapter` 适配不同类型的 Controller
   - 统一处理请求的逻辑

3. **JDBC 驱动**
   - 各种数据库驱动实现统一的 JDBC 接口
   - 应用程序无需关心具体数据库

4. **日志框架适配**
   - SLF4J 适配 Logback、Log4j、Jul 等
   - 统一日志 API

5. **天气服务转换**（本示例）
   - 将日本天气服务适配为中国接口
   - 进行单位转换和语言翻译

## 七、与其他模式的关系

### 7.1 适配器模式 vs 代理模式

| 对比项 | 适配器模式 | 代理模式 |
|--------|-----------|---------|
| **目的** | 改变接口，让不兼容的类可以工作 | 接口不变，控制对对象的访问 |
| **关系** | 实现不同的接口 | 实现相同的接口 |
| **关注点** | 接口转换 | 访问控制、增强功能 |

### 7.2 适配器模式 vs 装饰器模式

| 对比项 | 适配器模式 | 装饰器模式 |
|--------|-----------|-----------|
| **目的** | 接口转换 | 增强功能 |
| **接口** | 改变接口 | 保持接口不变 |
| **关注点** | 兼容性 | 功能扩展 |

### 7.3 适配器模式 vs 桥接模式

| 对比项 | 适配器模式 | 桥接模式 |
|--------|-----------|---------|
| **目的** | 接口转换 | 抽象与实现分离 |
| **时机** | 事后补救 | 事先设计 |
| **结构** | 一对一包装 | 多维度组合 |

### 7.4 适配器模式 vs 外观模式

| 对比项 | 适配器模式 | 外观模式 |
|--------|-----------|---------|
| **目的** | 适配单个对象 | 简化复杂子系统 |
| **对象数量** | 通常一个 | 多个 |
| **接口** | 转换接口 | 提供统一高层接口 |

## 八、最佳实践

### 8.1 设计建议

1. **优先使用对象适配器**
   - 耦合度更低
   - 更符合设计原则

2. **不要滥用适配器**
   - 如果能重新设计，优先重新设计接口
   - 适配器是"补救"措施，不是首选

3. **适配器应该简单**
   - 只做接口转换，不做复杂逻辑
   - 保持适配器的纯粹性

4. **文档化适配器**
   - 明确说明适配的是哪个类
   - 说明转换的逻辑

### 8.2 扩展示例

**新增适配器：**

1. 创建新的被适配者（如 `Power110V`）
2. 创建或复用目标接口（如 `Power5V`）
3. 创建适配器（如 `Power110VTo5VAdapter`）

**无需修改任何现有代码**！

## 九、总结

适配器模式是一种常用的结构型模式，它通过**接口转换**让不兼容的类可以协同工作。

**关键要点：**
- 目标接口：客户端期望的接口
- 被适配者：需要适配的现有类
- 适配器：实现接口转换的桥梁
- 对象适配器优于类适配器（推荐组合）

**两种主要实现方式：**
```
类适配器：继承 Adaptee + 实现 Target（不推荐）
对象适配器：组合 Adaptee + 实现 Target（推荐）⭐
```

**经典应用：**
- Java I/O 流中的 `InputStreamReader`
- Spring MVC 的 `HandlerAdapter`
- 各种日志框架适配器

适配器模式就像"翻译官"，让不同"语言"的类能够相互"交流"，是系统集成和代码复用的重要工具！
