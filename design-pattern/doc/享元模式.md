# 享元模式

## 一、概述

**享元模式（Flyweight Pattern）** 是一种结构型设计模式，它运用共享技术有效地支持大量细粒度的对象，避免对象拥有相同信息时造成内存浪费。

### 1.1 核心思想

- **共享对象**：相同状态的对象只创建一次，重复使用时直接返回
- **分离状态**：将对象状态分为内在状态（共享）和外在状态（不共享）
- **减少内存**：通过共享减少对象创建数量，降低内存占用

### 1.2 解决的问题

1. **内存占用过大**
   - 系统创建了大量相似对象
   - 这些对象只有部分状态不同

2. **对象重复创建**
   - 相同状态的对象被多次创建
   - 浪费内存和 CPU 资源

3. **性能问题**
   - 大量对象导致 GC 压力大
   - 系统响应变慢

### 1.3 关键概念

| 概念 | 说明 | 例子 |
|------|------|------|
| **内在状态 (Intrinsic State)** | 对象共享的、不变的信息 | 围棋棋子的颜色、奶茶的配方 |
| **外在状态 (Extrinsic State)** | 随环境变化的、不可共享的信息 | 棋子的位置、奶茶的糖度/冰度 |
| **享元工厂** | 管理共享对象的创建和获取 | 棋子工厂、奶茶工厂 |

### 1.4 生活中的例子

| 场景 | 内在状态（共享） | 外在状态（不共享） |
|------|-----------------|-------------------|
| **围棋游戏** | 棋子颜色（黑/白） | 棋子位置 (x, y) |
| **奶茶店** | 奶茶类型、配方、基价 | 糖度、冰度、杯型、顾客 |
| **共享单车** | 车型号、颜色、规格 | 位置、电量、编号 |
| **文本编辑器** | 字符样式、字体 | 字符位置、内容 |
| **电影院座位** | 座位类型、价格 | 座位号、售出状态 |
| **数据库连接池** | 连接配置 | SQL 语句、事务状态 |

## 二、模式结构

### 2.1 角色组成

1. **享元（Flyweight）** - [`GoPiece`](../src/main/java/com/coderlee/designpattern/structural/flyweight/gogame/GoPiece.java)、[`TeaDrink`](../src/main/java/com/coderlee/designpattern/structural/flyweight/milktea/TeaDrink.java)
   - 定义享元对象的接口
   - 声明接收外在状态的方法

2. **具体享元（Concrete Flyweight）** - [`BlackPiece`](../src/main/java/com/coderlee/designpattern/structural/flyweight/gogame/BlackPiece.java)、[`BubbleMilkTea`](../src/main/java/com/coderlee/designpattern/structural/flyweight/milktea/BubbleMilkTea.java)
   - 实现享元接口
   - 存储内在状态（可共享的部分）

3. **享元工厂（Flyweight Factory）** - [`GoPieceFactory`](../src/main/java/com/coderlee/designpattern/structural/flyweight/gogame/GoPieceFactory.java)、[`TeaDrinkFactory`](../src/main/java/com/coderlee/designpattern/structural/flyweight/milktea/TeaDrinkFactory.java)
   - 维护已创建的享元对象
   - 管理享元对象的创建和获取

4. **客户端（Client）** - [`GoBoard`](../src/main/java/com/coderlee/designpattern/structural/flyweight/gogame/GoBoard.java)、[`MilkTeaOrder`](../src/main/java/com/coderlee/designpattern/structural/flyweight/milktea/MilkTeaOrder.java)
   - 维护外在状态
   - 调用享元工厂获取享元对象
   - 将外在状态传递给享元对象

## 三、代码示例（围棋游戏）

### 3.1 享元接口

```java
// GoPiece.java - 围棋棋子接口
public interface GoPiece {
    void display(int x, int y);
    String getColor();
}
```

### 3.2 具体享元

```java
// BlackPiece.java - 黑子
public class BlackPiece implements GoPiece {
    private final String color = "黑子";  // 内在状态

    @Override
    public void display(int x, int y) {  // x, y 是外在状态
        System.out.printf("⚫ 黑子 位置：(%d, %d)\n", x, y);
    }

    @Override
    public String getColor() {
        return color;
    }
}

// WhitePiece.java - 白子
public class WhitePiece implements GoPiece {
    private final String color = "白子";  // 内在状态

    @Override
    public void display(int x, int y) {
        System.out.printf("⚪ 白子 位置：(%d, %d)\n", x, y);
    }

    @Override
    public String getColor() {
        return color;
    }
}
```

### 3.3 享元工厂

```java
// GoPieceFactory.java - 棋子工厂
public class GoPieceFactory {
    private static final Map<String, GoPiece> pieceMap = new HashMap<>();

    public static GoPiece getPiece(String color) {
        if (pieceMap.containsKey(color)) {
            return pieceMap.get(color);  // 复用已有对象
        }

        GoPiece piece = "黑".equals(color)
            ? new BlackPiece() : new WhitePiece();
        pieceMap.put(color, piece);
        return piece;
    }
}
```

### 3.4 客户端

```java
// GoBoard.java - 棋盘
public class GoBoard {
    public void placePiece(String color, int x, int y) {
        GoPiece piece = GoPieceFactory.getPiece(color);
        piece.display(x, y);  // 传入外在状态（位置）
    }
}
```

### 3.5 效果对比

**不使用享元模式：**
```java
// 每个棋子都创建新对象
for (int i = 0; i < 180; i++) {
    pieces[i] = new GoPiece(color, x, y);  // 180 个对象
}
```

**使用享元模式：**
```java
// 只创建 2 个对象（黑子和白子）
GoPiece black = GoPieceFactory.getPiece("黑");  // 创建 1 次
GoPiece white = GoPieceFactory.getPiece("白");  // 创建 1 次
for (int i = 0; i < 180; i++) {
    GoPieceFactory.getPiece(color).display(x, y);  // 复用
}
```

**内存节省：180 个对象 → 2 个对象**

## 四、代码示例（奶茶店）

### 4.1 享元接口

```java
// TeaDrink.java - 奶茶类型接口
public interface TeaDrink {
    void make(String sugarLevel, String iceLevel, String cupSize, String customerName);
    String getName();
    double getBasePrice();
}
```

### 4.2 具体享元

```java
// BubbleMilkTea.java - 珍珠奶茶
public class BubbleMilkTea implements TeaDrink {
    // 内在状态（共享）
    private final String name = "珍珠奶茶";
    private final String recipe = "红茶底 + 牛奶 + 珍珠";
    private final double basePrice = 15.0;

    @Override
    public void make(String sugarLevel, String iceLevel,
                     String cupSize, String customerName) {
        //外在状态（不共享）
        System.out.printf("🧋 %s 的 %s [￥%.2f]\n",
                          customerName, name, getFinalPrice(cupSize));
        System.out.printf("   定制：%s 糖，%s, %s\n",
                          sugarLevel, iceLevel, cupSize);
    }
}
```

### 4.3 享元工厂

```java
// TeaDrinkFactory.java - 奶茶工厂
public class TeaDrinkFactory {
    private static final Map<String, TeaDrink> drinkMap = new HashMap<>();

    public static TeaDrink getDrink(String type) {
        if (drinkMap.containsKey(type)) {
            return drinkMap.get(type);  // 复用
        }

        TeaDrink drink = switch (type) {
            case "珍珠奶茶" -> new BubbleMilkTea();
            case "芝士奶盖茶" -> new CheeseMilkTea();
            case "水果茶" -> new FruitTea();
            default -> throw new IllegalArgumentException("不支持的类型");
        };

        drinkMap.put(type, drink);
        return drink;
    }
}
```

### 4.4 客户端

```java
// MilkTeaOrder.java - 订单
public class MilkTeaOrder {
    public void placeOrder(String drinkType, String sugarLevel,
                          String iceLevel, String cupSize,
                          String customerName) {
        TeaDrink drink = TeaDrinkFactory.getDrink(drinkType);
        drink.make(sugarLevel, iceLevel, cupSize, customerName);
    }
}
```

## 五、两种状态的区分

### 5.1 内在状态 (Intrinsic State)

**特点：**
- 存储在享元对象内部
- 可以被多个对象共享
- 不随环境变化而变化
- 在创建享元时确定

**例子：**
| 场景 | 内在状态 |
|------|---------|
| 围棋 | 棋子颜色（黑/白） |
| 奶茶 | 类型、配方、基础价格 |
| 共享单车 | 车型号、颜色、规格 |
| 文本编辑 | 字符、字体、字号 |

### 5.2 外在状态 (Extrinsic State)

**特点：**
- 由客户端维护
- 不可共享，每个对象独有
- 随环境变化而变化
- 作为参数传递给享元方法

**例子：**
| 场景 | 外在状态 |
|------|---------|
| 围棋 | 棋子位置 (x, y) |
| 奶茶 | 糖度、冰度、杯型、顾客 |
| 共享单车 | 位置、电量、编号 |
| 文本编辑 | 位置、行号、列号 |

### 5.3 状态区分原则

| 问题 | 判断标准 |
|------|---------|
| 这个状态能被共享吗？ | 能 → 内在状态 |
| 这个状态会变化吗？ | 会 → 外在状态 |
| 不同对象这个状态一样吗？ | 一样 → 内在状态 |

## 六、优缺点分析

### 6.1 优点

1. **大幅减少内存占用**
   - 相同状态的对象只创建一次
   - 适合大量相似对象的场景

2. **提高性能**
   - 减少对象创建和销毁的开销
   - 降低 GC 压力

3. **优化资源使用**
   - 共享占用资源较多的对象
   - 提高系统整体效率

### 6.2 缺点

1. **增加系统复杂度**
   - 需要区分内在状态和外在状态
   - 代码理解和维护成本增加

2. **外在状态维护成本**
   - 客户端需要维护外在状态
   - 线程安全问题需要注意

3. **可能的性能开销**
   - 每次调用需要传递外在状态
   - 大量参数传递可能影响性能

## 七、适用场景

### 7.1 适合使用享元模式的场景

1. **大量相似对象**
   - 对象数量庞大
   - 对象只有部分状态不同

2. **内存敏感应用**
   - 移动应用、游戏
   - 需要处理大量数据的系统

3. **对象可共享**
   - 对象状态可以明确分为内在和外在
   - 内在状态可以被多个对象共享

### 7.2 实际应用示例

1. **Java 字符串常量池**
   ```java
   String s1 = "hello";  // 从常量池获取
   String s2 = "hello";  // 复用同一个对象
   System.out.println(s1 == s2);  // true
   ```

2. **Java 包装类缓存**
   ```java
   Integer a = 127;  // 从缓存获取
   Integer b = 127;  // 复用
   System.out.println(a == b);  // true

   Integer c = 128;  // 超出缓存范围 (-128~127)
   Integer d = 128;
   System.out.println(c == d);  // false
   ```

3. **数据库连接池**
   - 连接配置共享
   - 连接对象复用

4. **线程池**
   - 线程对象复用
   - 减少创建销毁开销

5. **游戏开发**
   - 子弹、怪物、道具等对象复用
   - 地图瓦片（Tile）共享

## 八、与其他模式的关系

### 8.1 享元模式 vs 单例模式

| 对比项 | 享元模式 | 单例模式 |
|--------|---------|---------|
| **目的** | 减少对象数量 | 保证唯一实例 |
| **对象数量** | 可以有多个 | 只有一个 |
| **共享方式** | 按类型共享 | 全局唯一 |

### 8.2 享元模式 vs 工厂模式

- 享元模式通常使用工厂模式来管理对象
- 工厂模式关注创建，享元模式关注共享

### 8.3 享元模式 vs 对象池

| 对比项 | 享元模式 | 对象池 |
|--------|---------|-------|
| **状态** | 无状态或共享状态 | 可能有状态 |
| **复用方式** | 永久复用 | 借用 - 归还 |
| **典型应用** | 棋子、字符 | 数据库连接 |

## 九、最佳实践

### 9.1 设计建议

1. **明确区分状态**
   - 仔细分析哪些状态可共享
   - 外在状态由客户端维护

2. **使用工厂管理**
   - 用 Map 缓存已创建的对象
   - 提供获取对象数量的方法

3. **注意线程安全**
   - 工厂方法可能需要加锁
   - 外在状态传递要线程安全

4. **合理设置缓存**
   - 使用弱引用避免内存泄漏
   - 可以设置最大缓存数量

## 十、总结

享元模式是一种通过**共享技术**来优化内存使用的设计模式，特别适合处理大量相似对象的场景。

**关键要点：**
- 内在状态：可共享的、不变的信息
- 外在状态：不可共享的、变化的信息
- 享元工厂：管理共享对象的创建
- 内存优化：大幅减少对象创建数量

**设计原则：**
- 单一职责原则：工厂负责管理对象
- 开闭原则：新增类型无需修改现有代码

**经典应用：**
- Java 字符串常量池
- Java 包装类缓存（IntegerCache）
- 数据库连接池
- 线程池
- 游戏对象管理

**性能对比：**
```
不使用享元：180 个棋子 = 180 个对象
使用享元：180 个棋子 = 2 个对象 (黑子 + 白子)
内存节省：98.9%
```

享元模式是**内存优化**的利器，当你发现系统创建了大量相似对象时，不妨考虑使用它！
