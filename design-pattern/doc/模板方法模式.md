# 模板方法模式

## 一、概述

**模板方法模式（Template Method Pattern）** 是一种行为型设计模式，它定义一个操作中的**算法骨架**，将一些步骤延迟到子类中，使得子类可以不改变算法结构的情况下重定义算法中的某些特定步骤。

### 1.1 核心思想

- **算法骨架**：在抽象类中定义算法的整体流程
- **步骤延迟**：将某些步骤的实现延迟到子类
- **不变与变**：不变的部分由父类实现，变化的部分由子类实现

### 1.2 解决的问题

1. **算法复用**
   - 多个类有相同的算法流程
   - 只是某些步骤的实现不同

2. **代码重复**
   - 相同流程的代码在多处重复
   - 难以维护和扩展

3. **控制扩展**
   - 需要控制子类的扩展点
   - 防止子类修改算法骨架

### 1.3 生活中的例子

| 场景 | 算法骨架（不变） | 可变步骤 |
|------|----------------|---------|
| **制作饮料** | 烧水→冲泡→添加配料→装杯 | 冲泡什么、添加什么配料 |
| **外卖订单** | 接单→备餐→打包→配送 | 是否配送、是否发票 |
| **文件上传** | 验证→分片→上传→合并 | 如何获取大小、如何上传 |
| **旅游行程** | 出发→游览→用餐→返回 | 游览哪里、吃什么 |

## 二、模式结构

### 2.1 角色组成

1. **抽象类（Abstract Class）**
   - 定义模板方法和基本方法
   - 实现公共的、不变的步骤
   - 声明抽象方法供子类实现

2. **模板方法（Template Method）**
   - 定义算法的骨架
   - 按顺序调用基本方法
   - 通常使用 `final` 防止子类修改

3. **基本方法（Primitive Method）**
   - 算法的各个步骤
   - 可以是抽象方法、具体方法或钩子方法

4. **具体子类（Concrete Class）**
   - 实现抽象方法
   - 可以选择性重写钩子方法

## 三、实现方式一：基本模板方法

### 3.1 场景介绍

**制作奶茶**：所有奶茶的制作流程相同（烧水→泡茶→加料→搅拌→装杯），但泡茶方式和添加的配料不同。

### 3.2 核心代码

```java
// DrinkMaker.java - 抽象类
public abstract class DrinkMaker {
    // 模板方法：定义算法骨架（final 防止子类修改）
    public final void makeDrink() {
        boilWater();           // 具体方法
        brewTea();             // 抽象方法
        addIngredients();      // 抽象方法
        stir();                // 具体方法
        serve();               // 具体方法
    }

    protected void boilWater() {
        System.out.println("🔥 烧水：加热至 95°C");
    }

    protected abstract void brewTea();

    protected abstract void addIngredients();

    protected void stir() {
        System.out.println("🥄 搅拌：使配料混合均匀");
    }

    protected void serve() {
        System.out.println("🥤 装杯：封盖，准备出杯");
    }
}

// BubbleTeaMaker.java - 具体子类
public class BubbleTeaMaker extends DrinkMaker {
    @Override
    protected void brewTea() {
        System.out.println("🍵 泡茶底：红茶包浸泡 3 分钟");
    }

    @Override
    protected void addIngredients() {
        System.out.println("🧋 添加配料：珍珠 + 牛奶 + 糖浆");
    }
}
```

### 3.3 输出示例

```
=== 开始制作饮料 ===
🔥 烧水：加热至 95°C
🍵 泡茶底：红茶包浸泡 3 分钟
🧋 添加配料：珍珠 + 牛奶 + 糖浆
🥄 搅拌：使配料混合均匀
🥤 装杯：封盖，准备出杯
=== 饮料制作完成 ===
```

## 四、实现方式二：带钩子的模板方法

### 4.1 场景介绍

**外卖订单处理**：订单处理流程固定，但某些步骤可选（如是否需要配送、是否需要发票）。

### 4.2 什么是钩子方法？

**钩子方法（Hook Method）** 是一种特殊的方法，它有默认实现，子类可以选择性地重写它来定制算法流程，但不影响算法的整体结构。

### 4.3 核心代码

```java
// OrderProcessor.java - 抽象类
public abstract class OrderProcessor {
    public final void processOrder() {
        receiveOrder();
        prepareFood();
        packFood();
        arrangeDelivery();  // 包含钩子判断
        printReceipt();     // 包含钩子判断
        completeOrder();
    }

    // 钩子方法：是否需要配送
    protected boolean needDelivery() {
        return false;  // 默认不需要
    }

    // 具体方法：根据钩子决定流程
    protected void arrangeDelivery() {
        if (needDelivery()) {
            deliverToCustomer();
        } else {
            System.out.println("🚶 顾客自取/堂食");
        }
    }

    protected abstract void deliverToCustomer();

    // 钩子方法：是否需要发票
    protected boolean needInvoice() {
        return false;
    }

    protected void printReceipt() {
        System.out.println("🧾 打印订单小票");
        if (needInvoice()) {
            printInvoice();
        }
    }

    protected abstract void printInvoice();
}

// DeliveryOrderProcessor.java - 外卖订单
public class DeliveryOrderProcessor extends OrderProcessor {
    @Override
    protected boolean needDelivery() {
        return true;  // 外卖需要配送
    }

    @Override
    protected void deliverToCustomer() {
        System.out.println("🛵 安排配送：骑手配送至 " + address);
    }

    @Override
    protected boolean needInvoice() {
        return needInvoice;  // 根据顾客需求
    }
}
```

### 4.4 输出示例

```
=== 开始处理订单 ===
📱 接收订单：确认订单信息
👨‍🍳 备餐：制作餐品
📦 打包：装入包装袋
🛵 安排配送：骑手配送至 北京市朝阳区 xx 路 xx 号
🧾 打印订单小票
📄 打印发票：电子发票将发送至顾客邮箱
✅ 订单完成，感谢惠顾
=== 订单处理完成 ===
```

### 4.5 钩子方法的作用

| 作用 | 说明 |
|------|------|
| **可选步骤** | 子类可以选择是否执行某步骤 |
| **条件控制** | 根据条件决定是否执行 |
| **扩展点** | 提供扩展点但不强制实现 |

## 五、实现方式三：带回调的模板方法

### 5.1 场景介绍

**文件上传系统**：文件上传流程固定，但在上传过程中需要回调通知进度和结果。

### 5.2 核心代码

```java
// UploadCallback.java - 回调接口
public interface UploadCallback {
    void onStart();
    void onProgress(int progress, long uploadedSize, long totalSize);
    void onSuccess(String fileId, String url);
    void onFailure(int errorCode, String message);
}

// FileUploader.java - 抽象类
public abstract class FileUploader {
    public final void upload(String filePath, UploadCallback callback) {
        callback.onStart();

        if (!validateFile(filePath)) {
            callback.onFailure(400, "文件验证失败");
            return;
        }

        long fileSize = getFileSize(filePath);
        long uploadedSize = 0;

        while (uploadedSize < fileSize) {
            uploadChunk(filePath, chunkIndex, currentChunkSize);
            uploadedSize += currentChunkSize;

            // 回调：报告进度
            int progress = (int) (uploadedSize * 100 / fileSize);
            callback.onProgress(progress, uploadedSize, fileSize);
        }

        String fileId = mergeChunks(filePath, chunkCount);
        callback.onSuccess(fileId, generateUrl(fileId));
    }

    protected abstract long getFileSize(String filePath);
    protected abstract void uploadChunk(String filePath, int chunkIndex, long chunkSize);
    protected abstract String mergeChunks(String filePath, int chunkCount);
}

// ImageUploader.java - 图片上传器
public class ImageUploader extends FileUploader {
    @Override
    protected long getFileSize(String filePath) {
        return 5 * 1024 * 1024; // 5MB
    }

    @Override
    protected void uploadChunk(String filePath, int chunkIndex, long chunkSize) {
        System.out.println("⬆️ 上传图片分片 [" + chunkIndex + "]");
    }

    @Override
    protected String mergeChunks(String filePath, int chunkCount) {
        return "IMG-" + System.currentTimeMillis();
    }
}
```

## 七、三种实现方式对比

| 实现方式 | 特点 | 适用场景 |
|---------|------|---------|
| **基本模板方法** | 定义算法骨架，子类实现步骤 | 算法固定，步骤可变 |
| **带钩子的模板方法** | 增加可选步骤的控制 | 有条件执行的步骤 |
| **带回调的模板方法** | 执行过程中回调通知 | 需要报告进度/结果 |

## 八、优缺点分析

### 8.1 优点

1. **代码复用**
   - 公共代码在父类实现
   - 避免代码重复

2. **易于维护**
   - 算法流程集中管理
   - 修改流程只需修改父类

3. **控制扩展**
   - 只开放必要的扩展点
   - 防止子类随意修改算法

4. **符合开闭原则**
   - 对扩展开放（新增子类）
   - 对修改关闭（不修改父类）

### 8.2 缺点

1. **类数量增加**
   - 每个实现需要一个子类
   - 可能导致类的数量增多

2. **灵活性受限**
   - 算法流程固定
   - 不适合流程多变的场景

3. **继承的缺点**
   - 使用继承关系
   - 不支持运行时改变

## 九、适用场景

### 9.1 适合使用模板方法模式的场景

1. **算法流程固定**
   - 多个类有相同的算法流程
   - 只是某些步骤的实现不同

2. **需要控制扩展**
   - 只允许在特定点扩展
   - 不允许修改算法骨架

3. **代码复用需求**
   - 提取公共代码到父类
   - 减少代码重复

### 9.2 实际应用示例

1. **Servlet 的生命周期**
   ```java
   // HttpServlet 定义了服务流程
   // init() -> service() -> doGet()/doPost() -> destroy()
   ```

2. **Spring 的 JdbcTemplate**
   ```java
   // 定义数据库操作流程
   // 获取连接 -> 执行 SQL -> 处理结果 -> 释放连接
   ```

3. **JUnit 测试框架**
   ```java
   // 测试执行流程
   // setUp() -> testMethod() -> tearDown()
   ```

4. **构建工具（Maven/Gradle）**
   ```java
   // 构建生命周期
   // 清理 -> 编译 -> 测试 -> 打包 -> 部署
   ```

## 十、与其他模式的关系

### 10.1 模板方法模式 vs 策略模式

| 对比项 | 模板方法模式 | 策略模式 |
|--------|-------------|---------|
| **实现方式** | 继承 | 组合 |
| **复用粒度** | 算法骨架 | 完整算法 |
| **灵活性** | 较低 | 较高 |

### 10.2 模板方法模式 vs 工厂方法模式

- 工厂方法模式是模板方法模式的特例
- 工厂方法只关注创建对象的步骤

### 10.3 模板方法模式 vs 钩子模式

- 钩子模式通常作为模板方法的一部分
- 钩子提供可选的扩展点

## 十一、最佳实践

### 11.1 设计建议

1. **模板方法使用 final**
   - 防止子类修改算法骨架
   - 确保算法流程一致

2. **钩子方法要有默认值**
   - 默认实现应该是安全的
   - 子类可以选择不重写

3. **文档化扩展点**
   - 说明哪些方法可以重写
   - 说明重写的注意事项

### 11.2 避免过度使用

1. **算法流程变化频繁**
   - 不适合使用模板方法
   - 考虑策略模式

2. **步骤过多过复杂**
   - 考虑分解为多个模板
   - 或使用组合模式

## 十二、总结

模板方法模式是一种**行为型模式**，它通过**定义算法骨架**并将某些步骤延迟到子类，实现了代码复用和流程控制。

**关键要点：**
- 模板方法：定义算法骨架（final）
- 基本方法：算法的各个步骤
- 钩子方法：可选的扩展点

**三种实现方式：**
1. **基本模板方法**：算法固定，步骤可变
2. **带钩子的模板方法**：增加可选步骤控制
3. **带回调的模板方法**：执行过程中回调通知

**经典应用：**
- Servlet 生命周期
- Spring JdbcTemplate
- JUnit 测试框架
- 构建工具生命周期

模板方法模式让你能够**固定算法流程**同时**允许子类定制细节**，是实现代码复用的有效工具！
