# 装饰器模式

## 一、概述

**装饰器模式（Decorator Pattern）** 是一种结构型设计模式，它允许向现有对象添加新功能，同时不改变其结构。该模式通过创建一个装饰类包装原始对象，在运行时动态扩展功能。

### 1.1 核心思想

- **组合优于继承**：使用对象组合而不是继承来扩展功能
- **动态扩展**：可以在运行时动态地添加和移除功能
- **透明性**：装饰器与被装饰对象有相同的接口，对客户端透明
- **可嵌套**：装饰器可以嵌套使用，实现功能的叠加

### 1.2 解决的问题

1. **继承的局限性**
   - 继承是静态的，编译时确定，无法在运行时改变
   - 多重继承会导致类爆炸问题（M 种基础类型 × N 种功能 = M×N 个类）

2. **功能组合的灵活性**
   - 需要能够动态地添加和移除功能
   - 需要支持功能的自由组合

### 1.3 与相关模式的区别

| 模式 | 目的 | 关系 | 能否嵌套 |
|------|------|------|----------|
| **装饰器模式** | 增强对象功能 | 包装关系 | ✅ 可以嵌套 |
| **代理模式** | 控制访问对象 | 一对一代理 | ❌ 不能嵌套 |
| **桥接模式** | 分离抽象与实现 | 组合关系 | ❌ 不用于嵌套 |
| **继承** | 静态扩展功能 | 继承关系 | ❌ 编译时确定 |

## 二、模式结构

### 2.1 角色组成

1. **组件（Component）** - [`Coffee`](../src/main/java/com/coderlee/designpattern/structural/decorator/Coffee.java)
   - 定义抽象类或接口
   - 规定子组件的方法
   - 是被装饰对象的基类

2. **具体组件（Concrete Component）** - [`SimpleCoffee`](../src/main/java/com/coderlee/designpattern/structural/decorator/SimpleCoffee.java)
   - 组件的具体实现
   - 是被装饰的原始对象
   - 提供最基本的功能实现

3. **抽象装饰器（Decorator）** - [`CoffeeDecorator`](../src/main/java/com/coderlee/designpattern/structural/decorator/CoffeeDecorator.java)
   - 继承自组件类
   - 持有一个组件对象的引用
   - 将请求委托给被装饰的组件
   - 可以在委托前后添加额外行为

4. **具体装饰器（Concrete Decorator）**
   - [`MilkDecorator`](../src/main/java/com/coderlee/designpattern/structural/decorator/MilkDecorator.java) - 牛奶装饰器
   - [`SugarDecorator`](../src/main/java/com/coderlee/designpattern/structural/decorator/SugarDecorator.java) - 糖装饰器
   - [`MochaDecorator`](../src/main/java/com/coderlee/designpattern/structural/decorator/MochaDecorator.java) - 摩卡装饰器
   - [`WhippingDecorator`](../src/main/java/com/coderlee/designpattern/structural/decorator/WhippingDecorator.java) - 奶油装饰器
   - 实现具体的装饰逻辑
   - 添加新的状态或行为

## 三、代码示例

### 3.1 组件接口

```java
// Coffee.java - 组件抽象类
public abstract class Coffee {
    protected String description = "Unknown Coffee";

    public String getDescription() {
        return description;
    }

    public abstract double getCost();
}
```

### 3.2 具体组件

```java
// SimpleCoffee.java - 基础咖啡
public class SimpleCoffee extends Coffee {
    public SimpleCoffee() {
        this.description = "基础咖啡";
    }

    @Override
    public double getCost() {
        return 5.0;
    }
}
```

### 3.3 抽象装饰器

```java
// CoffeeDecorator.java - 抽象装饰器
public abstract class CoffeeDecorator extends Coffee {
    protected Coffee decoratedCoffee;

    public CoffeeDecorator(Coffee coffee) {
        this.decoratedCoffee = coffee;
    }

    @Override
    public String getDescription() {
        return decoratedCoffee.getDescription() + " + " + getAddonDescription();
    }

    @Override
    public double getCost() {
        return decoratedCoffee.getCost() + getAddonCost();
    }

    protected abstract String getAddonDescription();
    protected abstract double getAddonCost();
}
```

### 3.4 具体装饰器

```java
// MilkDecorator.java - 牛奶装饰器
public class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee coffee) {
        super(coffee);
    }

    @Override
    protected String getAddonDescription() {
        return "牛奶";
    }

    @Override
    protected double getAddonCost() {
        return 2.0;
    }
}
```

### 3.5 客户端使用

```java
// Client.java - 客户端测试
public class Client {
    public static void main(String[] args) {
        // 基础咖啡
        Coffee coffee = new SimpleCoffee();
        System.out.println(coffee.getDescription() + " = ￥" + coffee.getCost());

        // 添加牛奶
        coffee = new MilkDecorator(coffee);
        System.out.println(coffee.getDescription() + " = ￥" + coffee.getCost());

        // 添加摩卡和奶油（嵌套装饰）
        coffee = new WhippingDecorator(
            new MochaDecorator(coffee)
        );
        System.out.println(coffee.getDescription() + " = ￥" + coffee.getCost());
    }
}
```

**输出结果：**
```
基础咖啡 = ￥5.00
基础咖啡 + 牛奶 = ￥7.00
基础咖啡 + 牛奶 + 摩卡 + 奶油 = ￥12.50
```

## 四、优缺点分析

### 4.1 优点

1. **符合开闭原则**
   - 对扩展开放：可以轻松添加新的装饰器
   - 对修改关闭：无需修改现有代码

2. **比继承更灵活**
   - 可以动态地添加和移除功能
   - 支持运行时组合，而非编译时绑定

3. **避免类爆炸**
   - 使用组合代替继承
   - 可以自由组合多个装饰器

4. **符合单一职责原则**
   - 每个装饰器只负责一种功能的添加
   - 代码易于维护和复用

5. **支持装饰链/装饰栈**
   - 可以嵌套多层装饰器
   - 实现复杂功能的叠加

### 4.2 缺点

1. **增加代码复杂度**
   - 引入大量小类（每个装饰器一个类）
   - 对初学者理解有一定难度

2. **调试困难**
   - 多层嵌套装饰器时，调用栈较深
   - 排查问题时需要逐层跟踪

3. **对象创建复杂**
   - 需要层层包装创建对象
   - 可以结合建造者模式解决

4. **性能开销**
   - 每次调用都需要委托给被装饰对象
   - 多层装饰会增加调用开销

## 五、适用场景

### 5.1 适合使用装饰器模式的场景

1. **需要动态添加功能**
   - 功能在运行时确定
   - 用户可以选择性地添加功能

2. **不能或不想使用继承**
   - 类已经很多，继承会导致类爆炸
   - 某些语言不支持多重继承

3. **功能可以自由组合**
   - 多个功能可以叠加使用
   - 功能的添加和移除频繁

4. **对现有代码无侵入**
   - 不能修改原有类的代码
   - 需要在外部扩展功能

### 5.2 实际应用示例

1. **Java I/O 流**（经典应用）
   ```java
   // BufferedReader 装饰 InputStreamReader
   // InputStreamReader 装饰 FileInputStream
   InputStream fis = new FileInputStream("file.txt");
   Reader isr = new InputStreamReader(fis);
   BufferedReader br = new BufferedReader(isr);
   ```

2. **GUI 组件边框**
   - 基础组件：按钮、文本框
   - 装饰器：滚动条边框、阴影边框、颜色边框

3. **Web 过滤器链**
   - Servlet Filter 链式处理请求
   - 每个过滤器是一个装饰器

4. **咖啡/奶茶订单系统**（本示例）
   - 基础饮品：咖啡、茶
   - 配料装饰：牛奶、糖、摩卡、奶油等

5. **日志系统**
   - 基础日志器
   - 装饰器：时间戳、日志级别、颜色输出

## 六、与其他模式的关系

### 6.1 装饰器模式 vs 代理模式

| 对比项 | 装饰器模式 | 代理模式 |
|--------|-----------|---------|
| **目的** | 增强功能 | 控制访问 |
| **关注点** | 添加职责 | 访问控制、延迟加载 |
| **嵌套** | 支持多层嵌套 | 通常一对一 |
| **客户端感知** | 透明 | 可能感知 |

### 6.2 装饰器模式 vs 桥接模式

- **装饰器模式**：关注功能的动态添加
- **桥接模式**：关注抽象和实现的分离

### 6.3 装饰器模式 vs 策略模式

- **装饰器模式**：包装对象增强功能
- **策略模式**：封装可互换的算法

### 6.4 装饰器模式 vs 组合模式

- **装饰器模式**：一对一包装
- **组合模式**：树形结构处理部分 - 整体关系

### 6.5 与单例模式的结合

- 装饰器可以设计为单例（如无状态的装饰器）
- 例如：`SugarDecorator.getInstance(coffee)`

## 七、最佳实践

### 7.1 设计建议

1. **保持接口一致**
   - 装饰器和被装饰对象必须有相同的接口
   - 确保客户端可以透明地使用

2. **简化对象创建**
   - 使用工厂方法或建造者模式简化装饰链的创建
   - 避免客户端代码过于复杂

3. **避免过度装饰**
   - 控制装饰层级数
   - 过深的嵌套会影响性能和可维护性

4. **文档化装饰器**
   - 明确每个装饰器的作用
   - 说明装饰器的使用顺序是否有影响

### 7.2 扩展示例

参考代码目录，如需新增：

- **新增配料**：继承 `CoffeeDecorator` 类，实现 `getAddonDescription()` 和 `getAddonCost()`
- **新增基础咖啡**：继承 `Coffee` 类，如 [`SimpleCoffee`](../src/main/java/com/coderlee/designpattern/structural/decorator/SimpleCoffee.java)

**无需修改任何现有代码**，完全符合开闭原则！

### 7.3 简化创建 - 建造者模式结合

```java
// 可以使用建造者模式简化装饰链的创建
Coffee coffee = new CoffeeBuilder()
    .addMilk()
    .addSugar()
    .addMocha()
    .build();
```

## 八、总结

装饰器模式是一种强大的结构型模式，它通过**组合优于继承**的设计原则，实现了功能的动态扩展。相比继承，它提供了更高的灵活性和可扩展性，是应对功能组合问题的有效手段。

**关键要点：**
- 装饰器与被装饰对象有相同的接口
- 可以动态地添加和移除功能
- 支持多层嵌套，实现功能叠加
- 符合开闭原则和单一职责原则

**Java I/O 流的经典应用：**
```
FileInputStream → InputStreamReader → BufferedReader → readLine()
      ↓                ↓                  ↓
   字节流           转换流             缓冲流
 (被装饰)       (装饰器 1)          (装饰器 2)
```

装饰器模式让你能够像"搭积木"一样灵活地组合功能，是设计模式工具箱中不可或缺的一员！
