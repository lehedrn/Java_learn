# 外观模式

## 一、概述

**外观模式（Facade Pattern）** 是一种结构型设计模式，它为复杂系统提供一个统一的简化接口，让客户端更容易使用该系统。

### 1.1 核心思想

- **简化接口**：为复杂系统提供一个简化的入口
- **封装复杂性**：隐藏子系统的复杂性和依赖关系
- **降低耦合**：客户端与子系统解耦
- **易用性**：提供高级接口，让使用更简单

### 1.2 解决的问题

1. **系统复杂性**
   - 子系统有多个类和复杂的交互
   - 客户端需要了解多个组件才能使用

2. **高耦合度**
   - 客户端直接依赖多个子系统类
   - 子系统变化会影响客户端

3. **使用门槛高**
   - 需要调用多个方法才能完成一个功能
   - 调用顺序容易出错

### 1.3 生活中的例子

| 场景 | 说明 |
|------|------|
| **公司前台** | 访客只需向前台说明来意，前台负责联系相关部门 |
| **万能遥控器** | 一键观影模式，自动打开电视、音响、调暗灯光 |
| **银行柜台** | 客户只需与柜员交流，柜员处理后台多个系统 |
| **酒店总机** | 拨打一个号码可转接客房服务、前台、餐厅等 |
| **电脑开机按钮** | 按一个按钮，自动完成 CPU、内存、硬盘的初始化 |

## 二、模式结构

### 2.1 角色组成

1. **外观类（Facade）** - [`HomeTheaterFacade`](../src/main/java/com/coderlee/designpattern/structural/facade/HomeTheaterFacade.java)
   - 知道哪些子系统类负责处理请求
   - 将客户端请求委托给适当的子系统对象
   - 提供简化的统一接口

2. **子系统类（Subsystem）** - [`Projector`](../src/main/java/com/coderlee/designpattern/structural/facade/Projector.java)、[`SoundSystem`](../src/main/java/com/coderlee/designpattern/structural/facade/SoundSystem.java) 等
   - 实现系统的实际功能
   - 没有外观类的引用
   - 可以独立工作

## 三、代码示例

### 3.1 子系统类

```java
// Projector.java - 投影仪
public class Projector {
    public void on() {
        System.out.println("Projector: 投影仪开机");
    }

    public void off() {
        System.out.println("Projector: 投影仪关机");
    }

    public void setInput(String source) {
        System.out.println("Projector: 设置输入源为 " + source);
    }
}

// SoundSystem.java - 音响系统
public class SoundSystem {
    public void on() {
        System.out.println("SoundSystem: 音响开机");
    }

    public void setVolume(int level) {
        System.out.println("SoundSystem: 设置音量为 " + level);
    }

    public void play() {
        System.out.println("SoundSystem: 开始播放音频 🎵");
    }

    public void pause() {
        System.out.println("SoundSystem: 暂停播放");
    }

    public void off() {
        System.out.println("SoundSystem: 音响关机");
    }
}
```

### 3.2 外观类

```java
// HomeTheaterFacade.java - 家庭影院外观
public class HomeTheaterFacade {
    private Projector projector;
    private SoundSystem soundSystem;
    private Player player;
    private Lights lights;
    private PopcornPopper popcornPopper;

    public HomeTheaterFacade(Projector projector, SoundSystem soundSystem,
                             Player player, Lights lights, PopcornPopper popcornPopper) {
        this.projector = projector;
        this.soundSystem = soundSystem;
        this.player = player;
        this.lights = lights;
        this.popcornPopper = popcornPopper;
    }

    /**
     * 一键观影模式
     */
    public void watchMovie(String movie) {
        System.out.println("========== 准备观影 ==========");

        popcornPopper.on();
        popcornPopper.pop();

        lights.dim(30);

        projector.on();
        projector.setInput("HDMI-1");

        soundSystem.on();
        soundSystem.setVolume(50);

        player.on();
        player.play(movie);

        System.out.println("========== 观影准备就绪 ==========");
    }

    /**
     * 一键结束观影
     */
    public void endMovie() {
        System.out.println("========== 结束观影 ==========");

        player.stop();
        player.off();
        soundSystem.off();
        projector.off();
        lights.on();
        popcornPopper.off();

        System.out.println("========== 已关闭所有设备 ==========");
    }
}
```

### 3.3 客户端使用

```java
// FacadeDemo.java - 演示类
public class FacadeDemo {
    public static void main(String[] args) {
        // 创建所有子系统
        Projector projector = new Projector();
        SoundSystem soundSystem = new SoundSystem();
        Player player = new Player();
        Lights lights = new Lights();
        PopcornPopper popcornPopper = new PopcornPopper();

        // 创建外观类
        HomeTheaterFacade homeTheater = new HomeTheaterFacade(
                projector, soundSystem, player, lights, popcornPopper
        );

        // 一键观影（无需关心子系统的复杂操作）
        homeTheater.watchMovie("流浪地球");

        // 结束观影
        homeTheater.endMovie();
    }
}
```

## 四、优缺点分析

### 4.1 优点

1. **简化客户端使用**
   - 提供统一的高层接口
   - 客户端无需了解子系统细节
   - 降低使用门槛

2. **降低耦合度**
   - 客户端与子系统解耦
   - 子系统内部变化不影响客户端
   - 符合迪米特法则（最少知道原则）

3. **更好的可维护性**
   - 复杂性集中在外观类
   - 子系统可以独立修改
   - 易于理解和维护

4. **支持分层架构**
   - 可以为不同层次创建外观
   - 形成清晰的系统层次结构
   - 便于系统扩展

5. **灵活性强**
   - 可以在不修改外观的情况下使用子系统
   - 可以同时提供简单接口和复杂接口

### 4.2 缺点

1. **违反开闭原则**
   - 添加新功能可能需要修改外观类
   - 外观类可能变得臃肿

2. **外观类可能过大**
   - 所有复杂逻辑集中在外观类
   - 可能成为"上帝类"

3. **灵活性受限**
   - 客户端无法直接使用子系统的高级功能
   - 需要绕过外观类才能使用特殊功能

## 五、适用场景

### 5.1 适合使用外观模式的场景

1. **复杂系统的简化访问**
   - 系统有多个组件和复杂的依赖关系
   - 需要为普通用户提供简单接口

2. **层次化系统设计**
   - 为子系统入口点创建外观
   - 形成清晰的层次结构

3. **客户端与子系统解耦**
   - 减少客户端对子系统的依赖
   - 提高系统的可维护性

4. **遗留系统改造**
   - 为旧系统提供新接口
   - 保持向后兼容性

### 5.2 实际应用示例

1. **Java Servlet 上下文**
   ```java
   // ServletContext 是 Servlet 容器的外观
   ServletContext context = request.getServletContext();
   String path = context.getRealPath("/");
   ```

2. **SLF4J 日志框架**
   ```java
   // SLF4J 是多个日志框架的外观
   Logger logger = LoggerFactory.getLogger(MyClass.class);
   logger.info("日志消息");
   ```

3. **JDBC DriverManager**
   ```java
   // DriverManager 是 JDBC 驱动的外观
   Connection conn = DriverManager.getConnection(url, user, password);
   ```

4. **Spring Facade 服务**
   ```java
   // Spring 的 JdbcTemplate 是 JDBC 的外观
   jdbcTemplate.query("SELECT * FROM users", ...);
   ```

5. **计算机启动**（本示例）
   - 隐藏 CPU、内存、硬盘的复杂交互
   - 提供一个 start() 方法完成启动

## 六、与其他模式的关系

### 6.1 外观模式 vs 适配器模式

| 对比项 | 外观模式 | 适配器模式 |
|--------|---------|-----------|
| **目的** | 简化接口 | 转换接口 |
| **接口设计** | 重新设计新接口 | 适配现有接口 |
| **对象数量** | 多个子系统 | 通常一个被适配者 |
| **关系** | 一对多 | 一对一 |

### 6.2 外观模式 vs 代理模式

| 对比项 | 外观模式 | 代理模式 |
|--------|---------|---------|
| **目的** | 简化接口 | 控制访问 |
| **接口** | 可能与子系统不同 | 与被代理对象相同 |
| **复杂度** | 简化使用 | 可能增加功能 |

### 6.3 外观模式 vs 单例模式

- 外观类通常设计为单例（因为只需要一个入口）
- 两者可以结合使用

### 6.4 外观模式 vs 抽象工厂模式

- 外观提供简化的使用接口
- 抽象工厂提供创建对象的方法
- 可以结合使用：外观使用工厂创建子系统

## 七、最佳实践

### 7.1 设计建议

1. **外观类职责单一**
   - 只做接口简化和委托
   - 不要在外表类中实现业务逻辑

2. **支持子系统的直接使用**
   - 允许高级用户绕过外观直接使用子系统
   - 外观不是强制的封装

3. **避免外观类过大**
   - 如果外观类太大，可以考虑拆分
   - 按功能模块创建多个外观

4. **文档化外观接口**
   - 说明外观提供的方法
   - 说明子系统的限制

### 7.2 扩展示例

**新增观影模式：**

```java
// 在 HomeTheaterFacade 中添加
public void watchTV() {
    // 切换到电视模式
    projector.setInput("TV");
    soundSystem.setVolume(30);
    lights.on();
}

public void playGame() {
    // 切换到游戏模式
    projector.setInput("GAME");
    soundSystem.setVolume(80);
    lights.dim(10);
}
```

**无需修改任何现有代码！**

## 八、外观模式的两种形式

### 8.1 有外观类

客户端通过外观类访问子系统：

```java
HomeTheaterFacade facade = new HomeTheaterFacade(...);
facade.watchMovie("电影");  // ✅ 推荐
```

### 8.2 无外观类

客户端直接访问子系统（不推荐）：

```java
Projector projector = new Projector();
SoundSystem sound = new SoundSystem();
Player player = new Player();
// ... 需要操作 5 个类，调用十几个方法
```

**对比：**
| 方式 | 代码量 | 复杂度 | 维护性 |
|------|--------|--------|--------|
| 有外观 | 少 | 低 | 高 |
| 无外观 | 多 | 高 | 低 |

## 九、总结

外观模式是一种简单而实用的结构型模式，它通过**提供统一的高层接口**，让复杂系统更易于使用。

**关键要点：**
- 外观类：知道哪些子系统负责处理请求
- 子系统：实现实际功能，不知道外观的存在
- 简化接口：让客户端使用更简单
- 降低耦合：客户端与子系统解耦

**设计原则：**
- 迪米特法则（最少知道原则）：只与直接朋友通信
- 单一职责原则：外观只负责简化接口
- 开闭原则：对扩展开放（但有局限）

**经典应用：**
- Java 的 `DriverManager`、`ServletContext`
- SLF4J 日志框架
- Spring 的 `JdbcTemplate`

外观模式就像系统的"前台"或"总机"，让客户端只需与一个对象交互，就能完成复杂的操作！
